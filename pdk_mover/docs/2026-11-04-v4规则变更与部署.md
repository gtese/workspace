# 2026-11-04 v4 规则变更与部署记录

## 背景

v3 规则链过长（同内容去重 → `CONFLICT_POLICY` 分支 → 空目录回收），运维侧反馈两点问题：

1. 目标已存在同名文件时按策略跳过，导致上游重复上传的旧版永久冻结在中转区，需要人工 `cleanup_conflicts.sh` 定期清理。
2. 策略分支多，出问题难判断走了哪条路径。

v4 直接砍掉策略层：**目标存在就覆盖，源端不留**。

## v4 规则

| 场景 | 行为 |
|---|---|
| 目标目录存在、文件不存在 | `mv` 到目标，计 moved |
| 目标目录存在、同名文件存在 | 覆盖，计 overwritten |
| 目标父目录不存在（含子目录） | 保留源文件，告警（同目录只报一次），计 failed |
| 子目录中的文件 | 递归搬运，目标侧子目录须已存在 |
| 搬运后源端空目录 | `find -mindepth 1 -type d -empty -delete` 回收 |
| `DRYRUN=1` | 只打印计划，不移动、不删空目录 |

原子落地保留：先 `mv` 到 `.<名>.part.$$` 再 `rename` 为正式名，中断不会留下半截文件占正式名；失败时源文件保持原样。

# 5) 正式跑一轮

## 后续注意

- 覆盖不可逆：上游若误将旧版以同名上传，正式区会被旧版替换。必要时在交付流程上约束版本号命名。
- 新增节点或新增子目录时，正式区目录必须先建好，否则文件会停在中转区并持续告警。
- `cleanup_conflicts.sh` 在 v4 下基本不再需要（不再产生 conflict 冻结件），保留作历史工具。
