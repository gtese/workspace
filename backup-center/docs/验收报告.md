## 5.1 单点登录与权限实测（2026-11-18）

在 Keycloak 创建两个临时本地测试用户（一个加入 `Group_Roots`、一个不加），通过**真实浏览器等价的 OIDC 授权码流程**登录生产平台，测后已删除临时用户：

| 用例 | 结果 |
|---|---|
| `Group_Roots` 成员 SSO 登录 | `role=admin` |
| 非 `Group_Roots` 员工 SSO 登录 | `role=viewer` |
| admin 访问 `GET /api/users` | 200 |
| viewer 访问 `GET /api/users` | 403 |
| viewer `POST /api/plans` | 403 |
| viewer `PUT /api/settings/alerts` | 403 |
| 登录页 | OIDC 启用后显示「统一身份登录（Keycloak）」，并提示 Group_Roots=管理员、其他成员只读 |

> 期间修复：OIDC 请求 scope 含 Keycloak 未定义的 `groups` 导致 `invalid_scope`；改为 `openid profile email` 并由 client 级 mapper 输出 `groups`/`roles`，同时回调错误改为跳转登录页提示。

## 7. 下一步建议

1. 通知用户刷新本机 DNS 缓存（`sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder`），之后统一使用 `https://backup.tri.local`。
2. 创建 Keycloak client 与 `backup-admins`/`backup-operators` 组，启用 SSO。
3. 为 8 台 Linux 节点与 MacBook 批量接入：按文件选择目录，先做小范围（`/home` 或项目目录）再扩大。
4. 配置 NAS 存储库与异地副本（`restic copy`），每季度做恢复演练。
5. 配置 SMTP 告警并接入现有监控。
6. 评估 150 的 IO 与 Slurm 作业互相影响，必要时把仓库迁到独立 NAS。
