# backup-center 部署手册

> 目标主机：`172.16.50.150`（`eda.tri.local`，RHEL 8.10）
> 当前访问地址：`https://backup.tri.local`（DNS 已指向 `172.16.50.150`；旧域名 `eda.tri.local` 仍可访问作为兼容入口）
> 仓库默认位置：`/data2/backup/restic`（剩余约 19 TiB）

## 1. 前置条件

| 项 | 要求 |
|---|---|
| 主机 | 150 可 root 登录；443/8443 未被占用；`/data2` 可写 |
| 证书 | 企业通配证书 `*.tri.local`（fullchain + key）；企业根 CA 已加入客户端信任 |
| 身份 | Keycloak `sso.tri.local/realms/tri`（可选，先用本地账号） |
| DNS | `backup.tri.local -> 172.16.50.150`（已完成；旧 `eda.tri.local` 兼容） |
| 存储 | 本地目录或 NFS/CIFS/FTP（NFS/CIFS 需 NAS 侧为 `backup` 用户开放写权限） |
| 构建机 | Mac（可访问 GitHub 与 npm），已装 Go、Node/npm |

## 2. 在 Mac 上构建与打包

```bash
cd ~/deepseek/workspace/backup-center
GO=/opt/homebrew/bin/go ./scripts/build-agent.sh        # 三平台代理
./scripts/build-mountd.sh                                # 特权挂载助手（linux/amd64）
./deploy/stage-binaries.sh                               # restic/rclone/agent/install.sh -> deploy/dist
(cd ui && npm ci && npm run build)                       # 前端 -> server/public
```

校验：`deploy/dist/SHA256SUMS` 与 `deploy/bin/agent/SHA256SUMS` 存在且可校验。

## 3. 上传并安装服务端

```bash
tar czf /tmp/bc-src.tgz --exclude='ui/node_modules' --exclude='server/dev' \
  --exclude='deploy/bin' --exclude='deploy/dist' --exclude='.git' \
  -C ~/deepseek/workspace/backup-center .
tar czf /tmp/bc-dist.tgz -C ~/deepseek/workspace/backup-center/deploy/dist .
scp /tmp/bc-src.tgz /tmp/bc-dist.tgz \
    ~/Downloads/Certs/tri.local_wildcard_fullchain.crt \
    ~/Downloads/Certs/tri.local_wildcard.key root@172.16.50.150:/tmp/

ssh root@172.16.50.150 '
  rm -rf /tmp/backup-center-src /tmp/backup-center-dist
  mkdir -p /tmp/backup-center-src /tmp/backup-center-dist
  tar xzf /tmp/bc-src.tgz  -C /tmp/backup-center-src
  tar xzf /tmp/bc-dist.tgz -C /tmp/backup-center-dist
  chmod 600 /tmp/tri.local_wildcard.key
  bash /tmp/backup-center-src/deploy/install-server.sh \
    --src /tmp/backup-center-src --dist /tmp/backup-center-dist \
    --hostname backup.tri.local \
    --cert /tmp/tri.local_wildcard_fullchain.crt \
    --key  /tmp/tri.local_wildcard.key \
    --repo /data2/backup/restic'
```

安装脚本会：创建 `backup` 用户与目录、安装 Node/restic/rclone/mountd、部署 `server/` 与 `dist/`、写入 `/etc/backup-center/config.json`、安装并启动 systemd 服务、输出初始管理员密码文件路径。

验证：

```bash
curl -kfsS https://backup.tri.local/healthz        # 从 150 本机
curl -fsS  https://backup.tri.local/healthz        # 从信任企业 CA 的机器
systemctl status backup-center backup-mountd
```

## 4. 初始化存储库

1. 浏览器打开 `https://backup.tri.local`，用 `admin` + `/var/lib/backup-center/initial-admin.txt` 中的密码登录。
2. 「存储库」→ 新建：
   - 本地目录：`/data2/backup/restic`
   - NFS：`server=172.16.20.x`、`export=/fs/backup`、options `rw,hard,vers=4.1,_netdev`
   - CIFS：`server=nashf5000.tri.local`、共享名、账号密码（自动写入 0600 凭据文件）
   - FTP(S)：主机/端口/账号/目录（rclone mount，实验性）
3. 点击「校验」，应返回成功且目录可写。
4. 首次登录后立即修改管理员密码，并删除 `initial-admin.txt`。

## 5. 接入客户端

1. 「待审批」→「生成接入令牌」，选择目标存储库。
2. 在目标主机执行页面给出的命令（Linux/macOS 通用）：

```bash
curl -fsSL https://backup.tri.local/agent/install.sh -o /tmp/bc-install.sh
sudo bash /tmp/bc-install.sh --server https://backup.tri.local:8443 --token <一次性 token>
```

脚本会下载代理与 restic（来自 `https://backup.tri.local/agent/dist/`）、安装 systemd/launchd 服务、提交注册并等待审批。

3. 审批通过后代理自动取回证书并启动；「节点管理」应显示在线。
4. **macOS 额外步骤**：系统设置 → 隐私与安全性 → 完全磁盘访问权限，添加 `/opt/backup-center-agent/bin/backup-agent`（否则 `~/Library` 部分目录不可读）；建议先在试点机验证 `launchd` 与服务自启。

## 6. 创建备份计划

「备份计划」→ 新建：选择节点、存储库、目录（可用目录选择器多选）、排除规则、cron（默认 `30 23 * * *`）、窗口、压缩、限速、保留策略、启停。保存后点「立即运行」验证。

## 6.1 切换域名

```bash
# 仅检查（DNS、443 健康检查），不修改配置
sudo ./deploy/switch-hostname.sh backup.tri.local 172.16.50.150 --check
# 确认后执行切换（更新服务端 public_url/agent_url/OIDC 回调 + 本机代理 server，并重启）
sudo ./deploy/switch-hostname.sh backup.tri.local 172.16.50.150
```

注意：若由 `172.16.50.122` 做反向代理，必须同时把 **8443/TCP** 转发到 `172.16.50.150:8443`（代理 mTLS 与仓库数据面需要直连），否则节点无法接入。

## 7. 升级

```bash
# Mac 重新构建、打包、上传后：
ssh root@172.16.50.150 'bash /tmp/backup-center-src/deploy/upgrade.sh /tmp/backup-center-src /tmp/backup-center-dist'
```

升级前会备份旧 `server/` 与 `dist/` 到 `/var/backups/backup-center/<时间戳>/`。

## 8. 卸载

```bash
ssh root@172.16.50.150 'bash /tmp/backup-center-src/deploy/uninstall-server.sh'          # 保留数据
ssh root@172.16.50.150 'bash /tmp/backup-center-src/deploy/uninstall-server.sh --purge'  # 删除程序与本地数据（仓库目录需人工确认）
```

## 9. Keycloak SSO 与 Group_Roots 管理权限

目标权限模型：

| 身份 | 角色 | 能力 |
|---|---|---|
| AD 组 `Group_Roots` 成员（经 SSO） | admin | 全部管理（节点审批、计划、恢复、用户、设置） |
| 其他企业员工（经 SSO） | viewer | 只读（查看节点/计划/快照/下载；不能修改或恢复） |
| 本地 `admin` 账号 | admin | 仅应急（断网/IdP 故障时使用） |

### 9.1 一键配置 Keycloak（推荐）

在 Mac 上执行（脚本幂等，可重复运行）：

```bash
cd ~/deepseek/workspace/backup-center
# 把 Keycloak 管理员口令放入 ~/.mm/keycloak-admin（0600），不要贴到聊天/日志
chmod 600 ~/.mm/keycloak-admin
python3 deploy/keycloak-setup.py --admin-password-file ~/.mm/keycloak-admin \
  --write-secret /tmp/backup-center-oidc.secret
```

脚本会：
1. 创建/更新 confidential client `backup-center`（授权码 + PKCE，回调 `https://backup.tri.local/auth/oidc/callback`）；
2. 添加 `groups`、`roles` claims mapper；
3. 创建 realm 角色 `backup:admin` 并授予 AD 组 `Group_Roots`。

### 9.2 启用服务端 OIDC

在 150 上执行（把 `client_secret` 写入配置后重启）：

```bash
cp /etc/backup-center/config.json /etc/backup-center/config.json.bak
service_secret=$(cat /tmp/backup-center-oidc.secret)
python3 - "$service_secret" <<'PY'
import json, sys
p='/etc/backup-center/config.json'
d=json.load(open(p))
d['oidc']['enabled']=True
d['oidc']['client_id']='backup-center'
d['oidc']['client_secret']=sys.argv[1].strip()
d['oidc']['admin_group']='Group_Roots'
d['oidc']['admin_role']='backup:admin'
d['oidc']['operator_group']=''
json.dump(d,open(p,'w'),ensure_ascii=False,indent=2)
PY
chown root:backup /etc/backup-center/config.json && chmod 0640 /etc/backup-center/config.json
systemctl restart backup-center
rm -f /tmp/backup-center-oidc.secret
```

登录页会出现「统一身份登录（Keycloak）」；`Group_Roots` 成员登录后为管理员，其他员工为只读。

### 9.3 手工方式（Keycloak 控制台）

1. Realm `tri` → Clients → Create client：`backup-center`，Client authentication 开，Standard flow 开，PKCE（S256）；
2. Valid redirect URI：`https://backup.tri.local/auth/oidc/callback`；Web origins：`https://backup.tri.local`；
3. Client scopes → dedicated mapper：`groups`（Group Membership，claim `groups`，full path off）与 `roles`（User Realm Role，claim `roles`）；
4. Realm roles 创建 `backup:admin`，Groups → `Group_Roots` → Role mapping 授予该角色；
5. 取 client secret，按 9.2 写入服务端配置。
