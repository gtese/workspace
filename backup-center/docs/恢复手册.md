# backup-center 恢复手册（实操版）

> 适用：TRI 集中备份平台生产环境（172.16.50.150 / https://backup.tri.local）
> 读者：备份管理员（Group_Roots）、值班运维、基础设施
> 原则：**先止损、再验证、后恢复**；恢复前确认目标与范围，严禁在未确认时对 `/` 做整快照覆盖。

## 0. 先看这里：恢复决策树

| 现象 | 场景 | 去哪个章节 |
|---|---|---|
| 误删/误改文件，系统正常 | 文件级恢复 | §2 |
| 某台业务机系统损坏/重装 | 单机全量恢复 | §3 |
| 150 服务起不来、DB/主机故障 | 控制面恢复 | §4 |
| 仓库盘损坏、快照读不出 | 仓库恢复 | §5 |
| master.key / CA / DB 丢失 | 密钥与 CA | §6 |
| Keycloak/AD 登录不了 | 身份故障 | §7 |
| 勒索/大规模误删 | 隔离与离线恢复 | §8 |
| 日常演练 | 验证与演练 | §9 |

**统一前置检查**（只读）：

```bash
systemctl status backup-center backup-center-agent backup-mountd --no-pager
curl -kfsS 'https://backup.tri.local/healthz?deep=1'
journalctl -u backup-center -n 100 --no-pager
```

## 1. 关键资产与真实路径

| 资产 | 生产位置 | 说明 |
|---|---|---|
| 主密钥 | `/var/lib/backup-center/master.key` | 32B；丢失则 DB 中仓库密码不可解 |
| 数据库 | `/var/lib/backup-center/backup.db` | 节点/计划/运行/审计 + 加密的仓库密码 |
| DB 本机备份 | `/var/lib/backup-center/db-backups/backup-YYYY-MM-DD.db` | 每日 03:00，保留 14 份，仅本机 |
| 平台 CA | `/var/lib/backup-center/ca/{ca.crt,ca.key,ca.srl}` | 代理证书签发；丢失需重新接入代理 |
| 服务端配置/TLS | `/etc/backup-center/{config.json,tls/}` | 含 OIDC secret、TLS 私钥，勿入 git |
| DR 口令 | `/etc/backup-center/dr.pass` | 控制面自动导出口令，0600；须离线托管 |
| 默认仓库 | `/data2/backup/restic`（`r_3e7e46cd5a0e`） | 每节点子目录 `<client_id>` |
| 项目仓库 | `/data2/backup/projects`（`r_82c25a669ac4`） | 每节点子目录 `<client_id>` |
| 程序 | `/opt/backup-center/{bin,server,dist}` | 服务端/代理分发/restic |
| 日志 | `/var/log/backup-center/`、journald | 审计与运行日志 |

| client_id | 主机 | 备份池 |
|---|---|---|
| `c_ea88171e27335af4` | 172.16.50.150 | `r_3e7e46cd5a0e`、`r_82c25a669ac4` |

## 2. 文件级恢复（最常用）

### 2.1 Web 操作（推荐，operator/admin）

1. 登录 →「快照」；
2. 选择 **节点** 与 **备份池**（默认池 / data2-projects），选择时间点；
3. 浏览目录，勾选文件/目录；可先「下载」验证内容；
4. 点击「恢复」：
   - 原地恢复：目标 `/`（仅 admin；operator 请用其他目标路径）；
   - **必须选择具体文件/目录**，空选择会被后端拒绝（400）；
   - 覆盖策略建议 `仅内容变化时覆盖`；
   - 首次可先勾选「干跑」看计划；
5. 到「恢复任务」查看进度/日志；完成后校验文件大小、mtime、sha256。

> 权限：`admin` 可原地恢复；`operator` 可**恢复到其他目标路径**（如 `/tmp/restore`），但不能原地覆盖原路径；`viewer` 只能浏览/下载。zhoutao 当前为 operator。

### 2.2 代理离线时

在快照浏览页直接**下载**单文件或目录 zip，再拷回目标机；下载同样写审计日志。

### 2.3 服务端命令行恢复（应急）

在 150 上，用恢复 CLI 取仓库密码（**只在控制台执行，不要重定向日志**）：

```bash
# 列出该节点的备份池（不打印密码）
/opt/backup-center/bin/node /opt/backup-center/server/src/recover.mjs \
  --config /etc/backup-center/config.json --client c_ea88171e27335af4

# 指定池，输出 RESTIC_REPOSITORY / RESTIC_PASSWORD 供当前 shell 使用
eval "$(/opt/backup-center/bin/node /opt/backup-center/server/src/recover.mjs \
  --config /etc/backup-center/config.json \
  --client c_ea88171e27335af4 --repo-id r_82c25a669ac4 --env)"

/opt/backup-center/bin/restic -r "$RESTIC_REPOSITORY" snapshots
/opt/backup-center/bin/restic -r "$RESTIC_REPOSITORY" ls <snapshot_id> /eda/workspace/projects
/opt/backup-center/bin/restic -r "$RESTIC_REPOSITORY" restore <snapshot_id> \
  --target /tmp/restore-$(date +%s) \
  --include '/eda/workspace/projects/TA2' \
  --overwrite if-changed \
  --exclude-xattr security.selinux \
  --verify
```

- 手工恢复先恢复到 `/tmp`，核对后再 `rsync/cp` 到目标路径；
- 不要在服务器上直接 `restore --target /`（权限、SELinux、覆盖风险）；
- `--include` 必须是具体路径，禁止空 include。

## 3. 单机全量恢复（业务机重装/损坏）

1. 重装同版本 OS，保持原主机名/IP（或重新规划）；
2. 用平台生成一次性 token，安装代理（Linux）：
   ```bash
   curl -kfsSL https://backup.tri.local/agent/install.sh -o /tmp/backup-center-install.sh
   sudo bash /tmp/backup-center-install.sh --server https://backup.tri.local:8443 --token <新token>
   ```
   - 配置文件：`/etc/backup-center-agent/config.json`
   - 服务：`systemctl status backup-center-agent`
   - macOS：`/Library/Application Support/backup-center-agent/config.json`，launchd `tri.backup.agent`
3. 在「待审批节点」批准（核对主机名/指纹/IP）；
4. Web「快照」→ 选该节点/池/时间点 → 选择需要恢复的目录（如 `/etc`、`/home`、项目目录）→ 恢复到 `/`；
5. 重启业务服务，验证数据与权限；必要时从旧机保留的配置对照。

**注意**：
- 系统盘重建后不要先手工 `restic init`；
- 恢复 `/etc` 前先备份当前 `/etc`，避免网络/证书配置被旧快照覆盖；
- 大目录建议分批恢复，避免一次性占满根分区。

## 4. 控制面恢复（150 主机/数据库故障）

### 4.1 同机服务故障（优先）

```bash
systemctl restart backup-center backup-mountd
journalctl -u backup-center -n 200 --no-pager
curl -kfsS https://backup.tri.local/healthz?deep=1
```

- 看 `/opt/backup-center`、`/var/lib/backup-center`、`/data2` 是否挂载；
- 磁盘满：先清理日志/临时文件，再启动；
- 不要删除 `/var/lib/backup-center` 下任何文件来“重装”。

### 4.2 重装/新机恢复控制面

1. 安装同版本服务端（`deploy/install-server.sh`），先不要初始化新库；
2. 停服务：
   ```bash
   systemctl stop backup-center backup-mountd
   ```
3. 从离线 DR 归档/本机备份恢复（顺序很重要）：
   ```bash
   install -m 600 master.key /var/lib/backup-center/master.key
   install -m 600 backup.db  /var/lib/backup-center/backup.db
   mkdir -p /var/lib/backup-center/ca
   cp -a ca/. /var/lib/backup-center/ca/
   # config.json / tls/ 按需恢复
   chown -R backup:backup /var/lib/backup-center/master.key /var/lib/backup-center/backup.db /var/lib/backup-center/ca
   ```
4. 确认仓库路径与配置一致（`/data2/backup/restic`、`/data2/backup/projects`）；
5. 启动并验证：
   ```bash
   systemctl start backup-center backup-mountd
   curl -kfsS 'https://backup.tri.local/healthz?deep=1'
   ```
6. 登录检查：节点在线、快照列表、计划、最近运行、审计；
7. 做一次**小文件恢复**验证（§2）。

### 4.3 使用自动 DR 导出（推荐）

- 脚本：`/opt/backup-center/bin/dr-export.sh`
- 口令：`/etc/backup-center/dr.pass`（必须离线托管，勿与介质同放）
- 目标：`/etc/backup-center/dr-export.env` 中 `DEST1`/`DEST2`（两个已挂载目录）
- 手动执行：
  ```bash
  sudo /opt/backup-center/bin/dr-export.sh
  ```
- 当前生产 timer 处于 **disabled**（尚未配置第二个真实离线目标）；挂载 NAS/USB 后：
  ```bash
  cp /etc/backup-center/dr-export.env.example /etc/backup-center/dr-export.env
  vi /etc/backup-center/dr-export.env       # 修改 DEST1/DEST2
  sudo /opt/backup-center/bin/dr-export.sh  # 先手工验证
  systemctl enable --now backup-center-dr-export.timer
  ```
- 解密：
  ```bash
  openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 \
    -pass file:/etc/backup-center/dr.pass \
    -in backup-center-dr-*.tar.gz.enc | tar xzf -
  ```

### 4.4 只有 DB 备份、没有 DR 包

- `/var/lib/backup-center/db-backups/backup-YYYY-MM-DD.db` 可恢复元数据，但**不包含 master.key/CA**；
- 必须另有 master.key 与 CA 的离线副本，否则仓库密码/代理证书无法恢复；
- 恢复旧 DB 后，最近计划/运行记录会回退，但 restic 仓库中的快照仍以仓库实际为准。

## 5. 仓库损坏/丢失恢复

### 5.1 判断范围

```bash
systemctl stop backup-center
# 以某节点默认池为例
/opt/backup-center/bin/restic -r /data2/backup/restic/<client_id> check
```

- 先查看 `/data2` 挂载、inode、磁盘 SMART；
- 不要对现有仓库执行 `init`/`prune`/`forget`；
- 立即停用相关计划，避免继续写入。

### 5.2 从副本恢复

- 优先使用**异地/离线 restic 副本**（`restic copy` 或存储快照）；
- 恢复目录到原路径后执行：
  ```bash
  /opt/backup-center/bin/restic -r /data2/backup/restic/<client_id> check
  /opt/backup-center/bin/restic -r /data2/backup/restic/<client_id> snapshots
  ```
- 校验通过后恢复计划，并做一次小文件恢复。

### 5.3 仓库完全丢失且无副本

- 该节点历史备份不可恢复；
- 只能重新初始化仓库并重新全备（会丢失历史时间点）；
- 必须升级为 P1 事件并复盘副本策略。

## 6. 密钥 / CA / DB 故障

| 故障 | 影响 | 处置 |
|---|---|---|
| `master.key` 丢失 | 所有仓库密码不可解，历史备份无法恢复 | 从离线 DR 恢复；无备份则不可恢复 |
| `master.key` 损坏 | 服务无法解密仓库密码 | 停服务，替换为离线副本，重启；先备份故障文件 |
| CA 私钥丢失 | 现有代理证书到期后无法续签；新代理无法签发 | 从 DR 恢复 CA；若确实丢失，重建 CA 后所有代理重新接入 |
| `backup.db` 损坏 | 节点/计划/密码密文丢失 | 停服务，用 `db-backups` 或 DR 包恢复；DB 丢失但 master.key/CA 在，仍需重建节点记录 |
| `config.json`/TLS 丢失 | 服务无法启动/HTTPS 失败 | 从 `/etc/backup-center` 备份或重装配置；TLS 可用企业证书重签 |

> **主密钥 + DB + CA 同时丢失** = 历史备份基本不可恢复；这也是要求三份资产分开/离线托管的原因。

## 7. Keycloak / AD 故障

1. 使用本地应急 `admin` 登录（仅应急，密码离线保管）；
2. 进入「用户与角色」，确认 Group_Roots 用户和预置域账号角色；
3. Keycloak 恢复后，Group_Roots 自动 admin；zhoutao 等预置 operator 可正常登录；
4. 未预置的 AD 账号仍会被拒绝，这是预期行为；
5. 若所有管理员都无法登录，用本地 `admin` 恢复；不要临时放开“所有域账号可登录”。

## 8. 勒索软件 / 大规模误删

1. **隔离**：断开 150 与受影响网段，停止代理服务，不要挂载备份盘到受感染主机；
2. 保留现场：不要执行 prune/forget/删除快照；
3. 优先从**离线/不可变副本**恢复（当前为手工加密导出/离线 USB，见 §4.3）；
4. 恢复后轮换：管理员口令、仓库密码、CA、代理证书；
5. 复核审计日志中的异常登录/下载/恢复；
6. 完成后按 BCP 文档复盘并补副本。

## 9. 验证与演练

### 9.1 恢复后检查清单

- [ ] `healthz?deep=1` 200，DB/仓库/restic/TLS 正常
- [ ] 代理在线（节点管理 last_seen）
- [ ] 快照列表可见（两个池）
- [ ] 小文件恢复成功、内容 sha256 一致
- [ ] 计划已启用、最近运行成功
- [ ] 审计日志记录恢复操作
- [ ] 容量/告警正常

### 9.2 自动恢复演练（每 30 天）

平台自动对每个「节点+池」从最新快照还原一个小文件并 `--verify`，结果在 `repo_checks kind=restore-drill`；失败告警 `restore_drill_failed`。

查看最近结果：

```bash
/opt/backup-center/bin/node -e "
const {DatabaseSync}=require('node:sqlite');
const db=new DatabaseSync('/var/lib/backup-center/backup.db');
console.log(db.prepare(\"SELECT client_id,repository_id,status,started_at,detail FROM repo_checks WHERE kind='restore-drill' ORDER BY started_at DESC LIMIT 10\").all());
"
```

### 9.3 人工全量演练（建议每半年）

1. 选非关键节点 + 小目录（如 `/etc`）；
2. 恢复到 `/tmp/restore-drill`，对比文件数/sha256；
3. 记录耗时（RTO 证据）与问题；
4. 更新离线密钥/DB 副本与演练记录。

## 10. 禁止事项

- ❌ 不要对现有仓库 `restic init`；
- ❌ 不要在未确认时恢复空 `includes` 或直接覆盖 `/`；
- ❌ 不要在故障盘上做 prune/forget/删除快照；
- ❌ 不要把 master.key、dr.pass、CA 私钥放入 git/聊天/普通日志；
- ❌ 不要用“重装/重新全备”替代恢复验证（历史时间点会丢失）；
- ❌ 不要在 Keycloak 故障时临时放开所有 AD 账号登录。
