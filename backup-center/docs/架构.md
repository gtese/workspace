# backup-center 架构与接口契约

> 版本：v1.0（2026-11-18）
> 本文件是服务端、代理、前端的**共同契约**。任何接口变更先改本文件。

## 1. 组成

| 组件 | 位置 | 技术 |
|---|---|---|
| 管理端 `backup-center` | `server/` | Node 24，零第三方依赖（`node:http/https/sqlite/crypto`） |
| 前端 | `ui/` → 构建到 `server/public` | Vue 3 + Vite 5 + Tailwind 3 + Pinia + ECharts + lucide |
| 代理 | `agent/` | Go（stdlib），静态二进制 linux/amd64、darwin/arm64、darwin/amd64 |
| 挂载助手 `backup-mountd` | `deploy/mountd/` | Go，root，Unix socket，管理 NFS/CIFS/FTP 挂载 |
| 数据面 | Node 内置 restic REST 协议实现（8443，mTLS） | restic 0.18.0 |
| 存储 | `/data2/backup/restic`（默认）或挂载点 | 本地/NFS/CIFS/FTP(S) |

## 2. 端口与身份

| 端口 | 用途 | 认证 |
|---|---|---|
| 443 | Web UI + 管理 API | Cookie 会话（Keycloak SSO / 本地账号）+ CSRF |
| 8443 | 代理 API + 仓库数据面 | **强制 mTLS**（平台 CA 签发客户端证书） |


- 仓库数据 URL：`https://<host>:8443/repo/<repo_id>/<client_id>/`，代理在传给 restic 前加 `rest:` 前缀，并通过 `RESTIC_TLS_CLIENT_CERT` 使用同一份 mTLS 证书。
- 代理不保存仓库密码；服务端在任务载荷里经 mTLS 下发，代理通过环境变量 `RESTIC_PASSWORD` 传给 restic。
- 平台 CA：`/etc/backup-center/ca/{ca.crt,ca.key}`；服务端 TLS 证书用企业通配证书 `*.tri.local`。

## 3. 数据模型（SQLite，WAL）

```sql

htpasswd(repo_id TEXT, username TEXT, password_enc TEXT, PRIMARY KEY(repo_id, username))
plans(id TEXT PK, name TEXT, client_id TEXT, repository_id TEXT,
      paths_json TEXT, excludes_json TEXT, cron TEXT, window_json TEXT,
      compression TEXT DEFAULT 'auto', limit_upload_kib INTEGER DEFAULT 0,
      retention_json TEXT, hooks_json TEXT, enabled INTEGER DEFAULT 1,
      created_by TEXT, created_at TEXT, next_run_at TEXT, last_run_at TEXT)
runs(id TEXT PK, plan_id TEXT, client_id TEXT, repository_id TEXT,
     trigger TEXT, status TEXT CHECK(status IN ('queued','running','success','failed','canceled','skipped')),
     started_at TEXT, finished_at TEXT, snapshot_id TEXT,
     files_new INTEGER, files_changed INTEGER, files_unmodified INTEGER,
     bytes_added INTEGER, bytes_processed INTEGER, error TEXT, log_tail TEXT)
restores(id TEXT PK, client_id TEXT, repository_id TEXT, snapshot_id TEXT,
     includes_json TEXT, target TEXT, overwrite TEXT, dry_run INTEGER,
     status TEXT, created_by TEXT, created_at TEXT, finished_at TEXT, error TEXT, log_tail TEXT)
repo_checks(id TEXT PK, repository_id TEXT, client_id TEXT, kind TEXT,
     status TEXT, detail TEXT, started_at TEXT, finished_at TEXT)
alerts(id TEXT PK, type TEXT, severity TEXT, message TEXT, client_id TEXT,
     created_at TEXT, acked_at TEXT)
audit_log(id INTEGER PK AUTOINCREMENT, at TEXT, actor TEXT, action TEXT,
     target TEXT, result TEXT, ip TEXT, detail_json TEXT)
settings(key TEXT PK, value TEXT)
schema_migrations(version INTEGER PK, applied_at TEXT)
```

字段说明：

- `paths_json` / `excludes_json`：JSON 数组；`retention_json`：`{keep_last,keep_daily,keep_weekly,keep_monthly,keep_yearly,prune_after_backup}`。
- `hooks_json`：`{pre:string|null, post:string|null}`（在客户端以 root 执行，仅管理员可设置）。
- `window_json`：`{start:"22:00", end:"06:00", skip_outside:true}`。
- `cert_serial`：代理证书序列号（大写十六进制），配 `cert_fp` 双重校验。
- 所有时间存入为 ISO8601 UTC（`new Date().toISOString()`）。

## 4. 通用约定

- JSON 请求/响应；错误体：`{"error":{"code":"<code>","message":"<中文或英文>"}}`，HTTP 状态码同步。
- 错误码：`unauthorized` `forbidden` `not_found` `conflict` `validation` `rate_limited` `internal`。
- Web 会话 Cookie：`bc_sid`（HttpOnly、SameSite=Lax、生产 Secure），TTL 8h。
- CSRF：`GET /api/auth/me` 返回 `csrf`；所有 `POST/PATCH/PUT/DELETE /api/*` 必须带 `x-csrf-token`（登录、OIDC 回调除外）。
- ID 格式：`c_`/`r_`/`p_`/`u_` + 12 hex；`run_`/`rst_`/`e_`/`t_` + 16 hex。
- 审计：所有写操作与恢复/下载必须写 `audit_log`，同时追加到 `<log>/audit.jsonl`。
- 权限：`admin` 全部；`operator` 管理节点/计划/运行/恢复（受 `user_scopes` 限制）；`viewer` 只读；`auditor` 只读 + 审计。

## 6. Agent API（8443，mTLS）

所有请求必须携带由平台 CA 签发且序列号在 `clients.cert_serial` 中的客户端证书。`/api/enroll` 除外（用一次性 token）。

### 6.1 注册（审批）

1. `POST /api/enroll`
```json
{"token":"<一次性>","hostname":"eda131","os":"rocky","os_version":"8.10",
 "arch":"amd64","agent_version":"0.1.0","csr_pem":"-----BEGIN CERTIFICATE REQUEST-----..."}
```
→ `202 {"request_id":"e_...","enroll_secret":"<随机>","poll_after_seconds":10}`
（代理把 `enroll_secret` 存 0600，仅用于轮询）

2. `GET /api/enroll/<request_id>`，Header `x-enroll-secret`：
- `202 {"status":"pending"}`
- `200 {"status":"approved","client_id":"c_...","cert_pem":"...","ca_pem":"...","config":{...}}`
- `410 {"status":"rejected"}`

审批通过时服务端：签发证书（CN=client_id，序列号入库）→ 建客户端记录（status=active）→ 在存储库根下建 `<client_id>/` 目录 → 生成 htpasswd 用户 + 随机密码（加密入库）。

### 6.2 运行期

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/agent/heartbeat` | `{agent_version,os,arch,uptime_seconds,restic_version,disks:[{path,total,free}],mounts:[...],active_task_id?}` → `{ok,next_poll_seconds}` |
| GET | `/api/agent/tasks?wait=25` | 长轮询；返回 `{tasks:[...]}`（空数组即超时） |
| POST | `/api/agent/tasks/:id/progress` | `{percent,bytes_done,bytes_total,files_done,files_total,current_path,message}` |
| POST | `/api/agent/tasks/:id/result` | `{ok,exit_code,snapshot_id,summary,error,log_tail}` |
| POST | `/api/agent/renew` | `{csr_pem}` → `{cert_pem}`（证书到期前 30 天） |
| GET | `/api/agent/dist/:version/:os/:arch` | 代理升级包（sha256 由服务端清单校验） |

### 6.3 任务载荷

```json
// backup
{"id":"t_...","type":"backup","run_id":"run_...","plan_id":"p_...",
 "repo":{"url":"https://backup.tri.local:8443/repo/r_x/c_y/","password":"<redacted>"},
 "host":"c_y","paths":["/home/docs"],"excludes":["*.tmp",".cache"],
 "tags":["plan:p_x"],"compression":"auto","limit_upload_kib":0,
 "hooks":{"pre":null,"post":null},"timeout_seconds":86400}

// restore
{"id":"t_...","type":"restore","restore_id":"rst_...",
 "repo":{"url":"...","password":"..."},"snapshot":"<full>",
 "includes":["/home/docs/a.txt"],"target":"/","overwrite":"always","dry_run":false}

// fs_list
{"id":"t_...","type":"fs_list","path":"/home"}

// upgrade
{"id":"t_...","type":"upgrade","version":"0.1.1","url":"https://.../dist/...","sha256":"..."}
```

代理执行 `restic` 时：

- 环境：`RESTIC_REPOSITORY=<url>`、`RESTIC_PASSWORD=<password>`、`RESTIC_CACHE_DIR=<cache>`、`RESTIC_PROGRESS_FPS=2`、`TMPDIR=<cache>/tmp`。
- 备份：`restic backup <paths...> --host <host> --tag <tags...> --exclude <pat...> --compression <mode> [--limit-upload <KiB>] --json`
- 恢复：`restic restore <snap> --target <target> --include <path>... --overwrite <mode> [--dry-run] --verify --json`
- fs_list 不调用 restic；返回目录项（`os.ReadDir` + `Lstat`）。

退出码：0 成功；1 失败；10 无仓库；11 仓库被锁；12 密码错误。代理把 stderr 尾部（最近 64KB）与摘要回传。

### 6.4 代理本地配置

Linux：`/etc/backup-center-agent/config.json`，macOS：`/Library/Application Support/backup-center-agent/config.json`。0600 root。

```json
{"server":"https://backup.tri.local:8443",
 "ca_file":".../ca.pem","cert_file":".../agent.crt","key_file":".../agent.key",
 "client_id":"c_...","restic_binary":"/opt/backup-center-agent/bin/restic",
 "cache_dir":"/var/cache/backup-center-agent","poll_wait_seconds":25,
```

## 7. 服务端内部约定

- restic 调用统一走 `server/src/restic.mjs`：`runRestic({repoPath|repoUrl,password,args,onJson,timeout,env})`。
- 仓库路径 = 存储库 `mountpoint`（如 `/data2/backup/restic`），客户端仓库 = `<mountpoint>/<client_id>`。
- **一个节点可属于多个备份池**：`client_repo_keys(client_id, repository_id)` 保存每个池独立的仓库密码；计划按 `repository_id` 选择池，运行/恢复/浏览均带该池；快照接口支持 `repository_id` 参数（缺省为客户端的默认池）。
- 备份源路径禁止落在任一存储库目录内；若选择仓库的父目录，服务端自动把仓库目录加入排除列表。
- 仓库数据面由 `server/src/restapi.mjs` 直接实现 restic REST 协议（create/list/HEAD/GET Range/POST/DELETE），只允许 `/repo/<repo_id>/<client_id>/**`；客户端证书序列号必须属于该 client_id，且 client.repository_id 必须等于路径中的 repo_id；DELETE 仅允许 `locks`（append-only）。
- restic 0.18 仓库格式 v2 的 pack 文件按 `data/<前两位十六进制>/<pack>` 分片存放；index/snapshots/keys/locks 平铺。
- 调度器每 10s 扫描；运行超时由服务端 watchdog 处理（标记 failed + 通知代理取消）。
- 敏感字段（仓库密码、存储凭据、SMTP 密码）用主密钥 AES-256-GCM 加密入库：`v1:<nonce>:<tag>:<ciphertext>`。主密钥 `/etc/backup-center/master.key`（32B，0600）。
- 日志：`<log>/server.log`（结构化 JSON 行）+ journald；审计单独 `audit.jsonl`。

## 9. 验收口径

- 未审批节点：`/api/agent/*` 无证书或证书不在白名单 → 401/403。
- 跨节点越权：用 c_A 证书访问 `/repo/r_x/c_B/` → 403。
- 未带 token/错误 token 的 enroll → 403。
- 恢复下载路径必须存在于快照；`..` 与绝对路径注入被拒。
- 所有写操作在 `audit_log` 有记录。
- 保留策略：`pinned` 快照不被 `forget` 删除。

## 10. v1.0 实现落地说明（2026-11-18）

1. **不再使用 rest-server**：REST 协议由 `server/src/restapi.mjs` 内置实现，减少一个二进制与一次反向代理；仓库数据面与 Agent API 共用 8443 mTLS 监听。
2. **代理与 restic 的 mTLS**：代理把 `agent.crt + agent.key` 合并写入 `<cache>/restic-tls.pem`（0600），通过 `RESTIC_TLS_CLIENT_CERT` 交给 restic 子进程；仓库 URL 在传给 restic 前自动加 `rest:` 前缀。
3. **开发模式端口**：Web `9443`、Agent API `9444`（HTTP 明文，无 mTLS）；生产 Web `443`、Agent API `8443`。
4. **注册批准响应**（`GET /api/enroll/<id>` 200）：
   ```json
   {"status":"approved","client_id":"c_...","cert_pem":"...","ca_pem":"...",
    "config":{"server":"https://backup.tri.local:8443","client_id":"c_...","poll_wait_seconds":25,
              "allowed_roots":"/","repository_id":"r_..."}}
   ```
5. **任务取消**：代理上报进度时，服务端返回 `{ok:true,cancel:false|true}`；`cancel=true` 时代理应终止 restic 并把任务标记为失败/取消。
6. **任务重投递**：已下发但 120 秒内未开始的备份/恢复任务会重新入队（最多 3 次），避免连接中断导致任务丢失。
7. **存储后端**：`local` 直接使用目录；`nfs`/`cifs`/`ftp` 由 root 权限的 `backup-mountd` 生成 systemd 挂载单元并校验 `backup` 用户可写。FTP 使用 rclone mount（实验性）。
8. **SSO 与权限模型**：OIDC 代码已实现（授权码 + PKCE + state/nonce + JWKS RS256 验签）。Keycloak 侧用 `deploy/keycloak-setup.py` 创建 client `backup-center`、claims mapper（groups/roles）、realm 角色 `backup:admin` 并授予 AD 组 `Group_Roots`；服务端把 `groups`/`roles` 中含 `Group_Roots` 或 `backup:admin` 的用户映射为 admin，其余一律 viewer（只读）。本地 admin 仅应急。
9. **域名**：`backup.tri.local` 已指向 172.16.50.150 并完成切换（旧 `eda.tri.local` 仍可访问）；告警通过 SMTP/Webhook 发送并落库，Web 端暂无独立告警列表页。
