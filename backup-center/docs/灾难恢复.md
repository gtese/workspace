# backup-center 灾难恢复（DR）手册

> 目标：在服务端主机故障、仓库损坏或误删时，能证明"数据可恢复"，并给出可执行步骤。

## 0. 实操恢复

日常恢复操作请优先按[恢复手册](恢复手册.md)执行；本文侧重资产托管、仓库副本与 DR 设计。

## 1. 必须离线托管的关键资产

| 资产 | 位置 | 说明 |
|---|---|---|
| 主密钥 | `/var/lib/backup-center/master.key`（32B） | **没有它，仓库密码无法解密，历史数据无法恢复** |
| 数据库 | `/var/lib/backup-center/backup.db` | 含节点、计划、运行、审计，以及用主密钥加密的仓库密码 |
| 平台 CA | `/var/lib/backup-center/ca/{ca.crt,ca.key}` | 代理证书签发；丢失会导致代理需重新注册 |
| 服务端配置/证书 | `/etc/backup-center/` | 含 OIDC secret、TLS 证书与私钥、挂载凭据 |
| 仓库数据 | `/data2/backup/restic/<client_id>/` | 加密后的实际备份数据 |

**托管方式（管理员 Mac）**：

```bash
mkdir -p ~/.mm/backup-center && chmod 700 ~/.mm/backup-center
scp root@172.16.50.150:/var/lib/backup-center/master.key \
    root@172.16.50.150:/var/lib/backup-center/backup.db \
    root@172.16.50.150:/var/lib/backup-center/ca/ca.key \
    root@172.16.50.150:/var/lib/backup-center/ca/ca.crt \
    ~/.mm/backup-center/
# /etc/backup-center/config.json 另行备份（含 secret，勿入 git）
```

建议每季度重新导出一次（数据库会变化）。

## 2. 仓库副本（异地/异机）

当前仓库与源数据同机，**不具备异地容灾**。至少做到：

```bash
# 方式一：整目录复制（离线/低峰期，先停备份任务）
rsync -a --delete /data2/backup/restic/ /mnt/nas/backup-restic/
# 方式二：restic copy 到另一个已初始化的仓库（推荐，可校验）
#   1) 用恢复 CLI 取出某节点仓库密码：
node /opt/backup-center/server/src/recover.mjs --config /etc/backup-center/config.json --client <client_id>
#   2) 在服务器上：
RESTIC_PASSWORD='<源仓库密码>' /opt/backup-center/bin/restic -r /data2/backup/restic/<client_id> \
  copy --repo rest:https://<目标 rest-server>/<client_id>/
```

副本目标可以是 NAS 挂载目录、另一台 rest-server，或对象存储（restic 支持 s3）。复制后必须在该目标上执行 `restic check`。

## 3. 恢复场景

### 3.1 单个/批量文件误删（最常见）

1. Web →「快照」→ 选节点/时间点 → 浏览 → 下载或「原地恢复」；
2. 恢复操作会写审计日志；
3. 若代理离线，可直接下载文件/目录 zip。

### 3.2 服务端故障（主机可重装）

1. 重装 150（或新机），执行 `deploy/install-server.sh`；
2. 恢复 `master.key`、`backup.db`、`ca/`、`config.json`、TLS 证书到原路径（权限 0600/0640）；
3. 把仓库目录挂回 `/data2/backup/restic`（或修改存储库路径）；
4. 启动服务，Web 应能看到原节点/快照；
5. 用「恢复」验证；代理若证书失效需重新接入。

### 3.3 仓库损坏/误删

1. 立即停用相关计划（Web → 计划 → 停用），防止新数据写入损坏仓库；
2. 从副本恢复仓库目录（或 `restic copy` 反向复制）；
3. 对每个节点执行 `restic check`（Web「节点详情」校验），必要时 `--read-data-subset=100%`；
4. 校验通过后恢复计划。

### 3.4 平台完全重建

1. 新机安装服务端；
2. 导入 `master.key`、`ca/`、`config.json`；
3. 仓库放在同一路径（或改配置后逐个节点改绑存储库）；
4. 数据库可选：若保留 `backup.db`，节点/计划/审计都在；若没有，需要重新创建节点并**用恢复 CLI + 手工 restic 直接读取旧仓库**：

```bash
node /opt/backup-center/server/src/recover.mjs --config /etc/backup-center/config.json \
  --client <old_client_id> --env
# 会输出 RESTIC_REPOSITORY / RESTIC_PASSWORD 两行
eval "$(node ... --env)"
/opt/backup-center/bin/restic -r "$RESTIC_REPOSITORY" snapshots
/opt/backup-center/bin/restic -r "$RESTIC_REPOSITORY" restore <snapshot> --target /tmp/restore --include <path>
```

## 4. 演练（每季度一次）

1. 选一个非关键节点，备份一个小目录；
2. 删除其中一个文件；
3. 在 Web 用快照恢复该文件；
4. 对比 sha256，记录到验收报告；
5. 抽查一个仓库执行 `restic check --read-data-subset=1%`；
6. 更新离线托管的密钥/数据库副本。

## 5. 离线导出记录

| 导出时间 | 归档 | SHA256 | 位置 |
|---|---|---|---|
| 2026-11-20 10:49 | `backup-center-dr-20261120-104905.tar.gz.enc` | `ef6420bf…beab8` | 介质1：`/Volumes/128G/backup-center-dr/`；介质2：待接入第二块离线盘（当前暂存 `~/.offline-backup/backup-center-dr/`） |

- 归档包含 `master.key`、`backup.db`（VACUUM INTO 快照）、`ca/` 与 `MANIFEST.sha256`；已用 AES-256-CBC + PBKDF2 加密。
- 解密口令单独保存在 `~/.offline-backup/backup-center-dr.pass`（0600），**不得与介质放在一起**；请转存密码管理器/保险柜后删除本地文件。
- 每次导出后应在本表记录时间、SHA256 与介质编号。

## 6. 注意事项

- **主密钥丢失 = 历史备份不可解**；仓库密码是每个节点独立随机生成的，只以密文存在于 `backup.db`。
- 不要在同一块故障盘上同时存"仓库"和"唯一密钥副本"。
- 恢复 CLI 输出含明文密码，只在服务器控制台执行，不要重定向到日志或聊天工具。
- 删除节点（Web）是软删除，仓库仍保留；如需彻底删除仓库数据，由管理员确认后手工删除目录。
