# backup-center 运维手册

> 主机：`172.16.50.150`（`eda.tri.local`）
> 服务：`backup-center.service`（Node 管理端）、`backup-mountd.service`（root 挂载助手）
> 仓库：`/data2/backup/restic/<client_id>/`（每个节点独立 restic 仓库）

## 1. 目录与端口

| 路径 | 用途 |
|---|---|
| `/opt/backup-center/bin/{node,restic,rclone,backup-mountd}` | 运行时与二进制 |
| `/opt/backup-center/server/` | 服务端代码与前端静态文件 |
| `/opt/backup-center/dist/` | 客户端安装脚本、代理与 restic 分发 |
| `/etc/backup-center/{config.json,tls/,ca/,storage/}` | 配置、TLS 证书、平台 CA、挂载凭据 |
| `/var/lib/backup-center/{backup.db,master.key,ca/,db-backups/}` | 数据库、主密钥、CA、数据库备份 |
| `/var/log/backup-center/{server.log,audit.jsonl}` | 服务日志与审计 |
| `/data2/backup/restic/` | 备份仓库 |
| `/mnt/backup-center/` | NFS/CIFS/FTP 挂载点 |

端口：443（Web + 管理 API）、8443（Agent API + 仓库数据面，强制 mTLS）。rest-server 已移除。

## 2. 启停与状态

```bash
systemctl status backup-center backup-mountd
systemctl restart backup-center
journalctl -u backup-center -f                   # 实时日志
journalctl -u backup-center --since "1 hour ago" | grep -i error
tail -f /var/log/backup-center/server.log
ls -l /run/backup-center/mountd.sock             # 应为 root:backup 0660
curl -kfsS https://127.0.0.1/healthz
```

## 3. 日常巡检（建议每日）

```bash
# 1) 服务与端口
systemctl is-active backup-center backup-mountd
ss -lntp | grep -E ':(443|8443)\b'
# 2) 健康
curl -kfsS https://127.0.0.1/healthz
# 3) 最近 24h 运行结果（在 Web 或 API）
# 4) 仓库容量
df -hT /data2
du -sh /data2/backup/restic/* 2>/dev/null | sort -h | tail
# 5) 数据库备份
ls -lt /var/lib/backup-center/db-backups | head
# 6) 证书到期（平台 CA 10 年；代理证书 1 年，自动续期）
openssl x509 -in /etc/backup-center/tls/server.crt -noout -dates
```

Web 控制台「概览」可看在线节点、24h 成功/失败、仓库容量；后端 `/api/metrics` 提供 Prometheus 指标（需 admin 会话）。

## 4. 常见故障

| 现象 | 排查 |
|---|---|
| 节点显示离线 | `systemctl status backup-center-agent`；`journalctl -u backup-center-agent`；确认到 150:8443 通、证书未过期 |
| 备份报 `403 Forbidden` on `/repo/...` | 代理证书序列号是否在库；节点的 `repository_id` 与 URL 是否一致；是否被停用 |
| 备份报 `unable to open config file` | 仓库目录是否存在、`backup` 用户可读；`restic check` 验证 |
| 任务一直 queued | 服务端 watchdog 会在 120s 后重投（最多 3 次）；检查代理是否在长轮询；必要时 `systemctl restart backup-center-agent` |
| 计划目标备份池报 403 | 确认该节点在该池已有 `client_repo_keys` 记录（首次计划运行会自动创建）；检查 `repository_id` 与 URL 是否一致 |
| 恢复报 `xattr ... security.selinux permission denied` | 已在 v1.0 恢复参数中自动 `--exclude-xattr security.selinux`；升级代理后重启即可 |
| 备份路径被拒绝 | 不能选择存储库自身目录；选择仓库父目录时服务端会自动排除仓库目录 |
| 仓库被锁定 | 确认无运行中的备份后：`sudo -u backup env RESTIC_PASSWORD=<...> /opt/backup-center/bin/restic -r <repo> unlock --remove-all`（密码从 Web 无法直接查看，可用「重新初始化」流程或联系平台管理员；一般无需人工清理） |
| 挂载后 `backup` 不可写 | NFS 侧需为 `backup` uid 开放写权限；CIFS 使用 `uid/gid=backup` 挂载；`journalctl -u backup-mountd` |
| 创建本地存储库提示"目录不可写" | 目录属主不是 `backup`（常见于 root 手工 mkdir）。执行 `chown -R backup:backup <目录>`；新版 mountd 会在 Web 创建本地存储库时自动创建目录并 chown，若仍失败查看 `journalctl -u backup-mountd` |
| 同一本地路径无法重复建库 | v1.0 起禁止两个存储库复用同一本地路径（409 conflict），请换路径或删除旧库 |
| FTP 挂载慢/失败 | rclone mount 对 FTP 语义较弱；建议改 NFS/CIFS；查看 `systemctl status backup-mount-<repo>.service` |
| 443 启动失败 | 端口被占用或证书/私钥不匹配；`ss -lntp \| grep :443`；`openssl x509`/`openssl rsa` 校验 |
| SELinux 拒绝 | `ausearch -m avc -ts recent`；按需生成最小策略模块；当前实测未触发 |

## 5. 保留与校验

- 计划成功后会按 `retention` 执行 `restic forget --keep-* --keep-tag pinned --prune`；同一节点 6 天内不重复 prune。
- 每周自动 `restic check`（结构校验），每月自动 `restic check --read-data-subset=1%`（抽样读校验）；结果存 `repo_checks`，失败会触发告警。
- 手动：Web「节点详情」或 `POST /api/clients/<id>/check`、`POST /api/clients/<id>/prune`。
- 钉住（pin）的快照打 `pinned` 标签，`forget` 不会删除。

## 6. 告警

Web「设置 → 告警」配置 SMTP / Webhook；本地测试按钮可用。告警类型：节点离线、备份失败、prune 失败、check 失败、仓库容量超阈值。告警落库（`alerts` 表）并通过 SMTP/Webhook 发送。

> SMTP 需内网中继；当前未配置时告警仅落库与日志。

## 7. 安全运维

```bash
# 审计日志（同时落 SQLite）
tail -f /var/log/backup-center/audit.jsonl
# 查看登录/恢复/删除动作
grep -E 'auth|restore|snapshot.delete' /var/log/backup-center/audit.jsonl | tail
# 主密钥与 CA 权限
ls -l /var/lib/backup-center/master.key /var/lib/backup-center/ca/
```

- 停用节点：Web「节点管理 → 停用」，证书立即失效（服务端按序列号白名单拒绝）。
- 换证书/续期：代理到期前 30 天自动续期；如手动轮换，删除该节点后重新接入。
- 管理员账号：本地 `admin` 仅应急；日常用 Keycloak SSO（配置后），按 `backup-admins`/`backup-operators` 映射角色。
- 敏感文件：`config.json` 含 OIDC secret 时为 0640 root:backup；`master.key`/CA 私钥 0600；不要把 `~/.mm`、主密钥、仓库密码提交到 git。

## 8. 资源与错峰

- `backup-center.service`：`MemoryMax=2G`、`CPUQuota=200%`、`LimitNOFILE=65536`、`IOWeight=100`。
- 默认备份窗口 22:00–06:00（计划可改）；prune 由成功备份后触发；校验在低峰期顺序执行。
- 150 同时是 Slurm 计算节点：大批量首次备份前建议先评估 `/data2` IO 与作业影响，必要时在计划里设置 `limit_upload_kib`。

## 9. 数据库与配置备份

- 每日 03:00 自动复制 SQLite 到 `/var/lib/backup-center/db-backups/backup-<date>.db`，保留 14 份。
- 手动：`sqlite3` 不可用，使用 `cp /var/lib/backup-center/backup.db /tmp/`（或停服务后复制）。
- 配置与证书清单：`tar czf /root/backup-center-config-$(date +%F).tgz /etc/backup-center`（含密钥，妥善保管）。

## 10. 容量规划

- 仓库增长 ≈ 源数据增量 × 去重率；建议仓库剩余空间 ≥ 预估年增量 × 2。
- 阈值：Web 看板与告警（默认 85%）；`/data2` 已用 34%（2026-11-18 实测），余约 19 TiB。
- 扩容：挂载新盘到 `/data2` 或新增存储库（NFS/CIFS），计划改绑新库；旧库保留只读供恢复。
