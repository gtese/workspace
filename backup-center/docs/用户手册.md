# backup-center 用户手册

> 地址：`https://backup.tri.local`（`backup.tri.local` 生效后自动切换）
> 登录：`Group_Roots` 成员经 SSO 自动成为管理员；其他域账号须先在「用户与角色」中新增 OIDC/SSO 用户并选择角色（operator/viewer/auditor），启用后即可登录。未预置账号会被拒绝。本地 admin 仅应急。

## 1. 角色

| 角色 | 权限 |
|---|---|
| admin（AD 组 `Group_Roots` 成员经 SSO，或本地应急 admin） | 全部：节点审批、存储库、计划、恢复、用户、审计、设置 |
| operator | 节点/计划/运行/恢复/存储库校验；不能增删用户、不能删快照（默认不分配） |
| viewer | 只读查看 |
| auditor | 只读 + 审计日志 |

## 2. 接入新节点（一次性 token 从哪来）

1. 「节点管理」右上角 **接入新节点**（或「待审批节点」页面）→ **生成接入命令**；
2. 在弹窗中填写：主机名提示（可选）、token 有效期（默认 60 分钟）、目标存储库（备份池）；
3. 点「生成」后，页面会给出：
   - **一次性 token**（随机生成，仅显示一次，可复制）；
   - 一条安装命令（**已内置企业根 CA**，先安装 CA 再用正常 TLS 校验下载脚本，无需 `curl -k`）：
     ```bash
     sudo bash -c '
     ...（页面生成，包含 CA_B64 与 token）
     curl -fsSL https://backup.tri.local/agent/install.sh -o /tmp/backup-center-install.sh
     bash /tmp/backup-center-install.sh --server https://backup.tri.local:8443 --token <一次性token>
     '
     ```
4. 在目标主机以 **root** 执行该命令；代理自动下载、生成密钥并提交注册；
5. 回到「待审批节点」核对主机名、系统、来源 IP、证书指纹 → **批准**；
6. 代理自动取回证书并启动，节点出现在「节点管理」。

token 规则：**单次使用、默认 60 分钟有效、绑定该次注册请求**；批准/拒绝/过期后即失效。丢失或过期就重新生成一条命令。

> 150 已经在节点列表里，不需要重复接入。

## 2.1 删除节点

「节点管理」→ 节点右侧「删除」：

- 节点会从列表和统计中移除，相关备份计划自动停用；
- 历史快照仍保留在对应存储库中（不会被删除），便于按时间点恢复或由管理员手工清理；
- 如需“彻底删除节点记录 + 仓库数据”，请单独确认后处理（避免误删备份）。

## 3. 选择要备份的目录/文件

1. 管理员在「待审批」页点「生成接入令牌」，选择存储库，复制安装命令。
2. 在目标主机（root）执行命令；安装脚本会自动下载代理与 restic、提交注册。
3. 管理员在「待审批」看到主机名/系统/指纹/来源 IP，点「批准」。
4. 节点出现在「节点管理」并显示在线状态（代理每 15–30 秒心跳）。

macOS 首次使用需在「系统设置 → 隐私与安全性 → 完全磁盘访问权限」中给 `/opt/backup-center-agent/bin/backup-agent` 授权。

## 3. 选择要备份的目录/文件

1. 「备份计划」→ 新建；
2. 点击「存储库 / 备份池」字段，会打开**存储库对象浏览器**（文件浏览器式弹窗），按名称/类型/路径搜索并直接选择 `data2-projects` 这样的对象；同一节点可以建多个计划，分别写入不同的备份池；
3. 点「选择目录」：目录树逐层展开（只读），可多选目录或文件，也可手工输入绝对路径；
4. 填写排除规则（支持 glob，如 `*.iso`、`.cache`、`node_modules`）；
5. 设置 cron、备份窗口、压缩（auto/max/off）、限速（KiB/s）、保留策略；
6. 保存后点「立即运行」验证首次全备。

## 4. 全备与增量

- 第一次运行是**全备**（所有文件上传）；
- 之后的运行都是**增量**（只上传变化/新增数据），但每个时间点都是完整可恢复的快照；
- 「运行任务」里可看到新增/修改/未变文件数与新增数据量。

## 5. 查看与恢复

### 5.1 浏览

「快照」→ 选节点 → 选**备份池 / 存储库** → 选时间点 → 目录树浏览/搜索文件名。

> 同一个节点可能同时写入多个备份池（如系统配置池、项目数据池）。快照页的「备份池」下拉用于切换查看；下载与恢复会自动带上该池，不需要手工指定仓库。

### 5.2 下载

- 单文件：点「下载」直接保存；
- 目录：点「下载 zip」，得到该目录的压缩包。

### 5.3 按时间点恢复（原地）

1. 「快照」→ 选择节点 → 选择**备份池 / 存储库**（例如 `data2-projects`）；
2. 在左侧时间点列表中点击要恢复的时间点（如 `2026-11-18 18:00:42`）；
3. 右侧目录树导航到目标目录（如 `/eda/workspace/projects/TA2`），勾选文件或目录；
4. 点「恢复」：
   - **目标路径**：默认 `/` 表示恢复到原始位置；想先验证可填 `/tmp/restore-test`；
   - **覆盖策略**：`always` / `if-changed` / `never`；
   - 可先勾选「干跑」预演（只读，不写文件）；
5. 提交后在「恢复任务」查看进度与日志；恢复操作写入审计日志。

> 恢复由客户端代理执行，需要节点在线；若节点离线，只能用「下载」单文件或目录 zip。
> restic 恢复时会自动跳过 `security.selinux` 扩展属性（目标机 SELinux 可能拒绝写入），文件内容/权限/时间仍完整恢复，SELinux 由系统按路径重新打标。

### 5.4 原地恢复

「恢复向导」→ 选择文件/目录 → 目标路径（默认 `/`）→ 覆盖策略（always/if-changed/never）→ 可先「干跑」→ 提交。
- 恢复由客户端代理执行，可在「恢复任务」看到实时进度与日志；
- 恢复操作会写入审计日志（谁、何时、从哪个快照恢复了哪些路径）。

### 5.4 钉住与删除

- 「钉住」：标记后保留策略不会删除该快照（重要时间点请钉住）；
- 「删除」：仅 admin 可操作，删除后不可恢复（除非仓库另有副本）。

## 5.5 两个“选择器”的区别

| 入口 | 打开方式 | 用途 |
|---|---|---|
| 目录选择器 | 备份范围旁的「选择目录」 | 选择**要备份的源目录/文件**（浏览节点文件系统、挂载点） |
| 存储库对象浏览器 | 计划编辑器的「存储库 / 备份池」字段 | 选择**备份数据写入哪个池**（如 `data2-projects`），展示类型/路径/容量/状态，可搜索 |

## 5.6 保留策略怎么理解

保留策略由 restic 的 5 个「keep」规则组成，**取并集**：一个快照只要命中任一规则就会被保留，其余删除。

| 字段 | 含义 |
|---|---|
| 保留最近 N | 保留**最近 N 个快照**（按运行次数，不是天数）。例如每天跑 4 次、N=14，只能覆盖约 3.5 天。 |
| 保留每日 N | 在**最近 N 个有备份的日期**里，每个日期保留最新 1 个快照（不是每天留 N 个）。 |
| 保留每周 N | 在最近 N 个有备份的自然周里，每周保留最新 1 个。 |
| 保留每月 N | 在最近 N 个有备份的月份里，每月保留最新 1 个。 |
| 保留每年 N | 在最近 N 个有备份的年份里，每年保留最新 1 个。 |

补充规则：

- **钉住的快照**（`pinned` 标签）永远不会被删除，与上述规则无关。
- 「备份完成后自动清理」= 成功备份后执行 `restic forget --keep-* --prune`；`forget` 只删除快照引用，`--prune` 才回收数据空间。
- 为避免 IO 抖动，同一节点 + 同一备份池最多约 **6 天执行一次**自动 prune；手动可在节点详情触发。
- 保留策略按**计划**保存，清理作用于该计划对应的**备份池**（同一节点不同池互不影响）。

### 示例：截图中的 14 / 1 / 1 / 1 / 1

- 实际效果 ≈ **保留最近 14 个快照**（每日/周/月/年各 1 条通常都包含在这 14 个里，属于“兜底”）。
- 每天备份 1 次 → 约 14 天历史；每天 4 次 → 约 3.5 天。
- 想同时保留“最近 14 天 + 每周 + 每月”，建议改成：
  - 保留最近 3、每日 14、每周 8、每月 12、每年 3
  - 或按容量：最近 2、每日 7、每周 4、每月 6、每年 1

## 6. 运行与告警

- 「运行任务」：每 2 秒刷新进度，可取消；失败可查看日志尾部；
- 「概览」：在线节点、24h 成功/失败、仓库容量；
- 告警通过邮件/Webhook 发送（需管理员在「设置」配置 SMTP）。

## 7. 常见问题

| 问题 | 处理 |
|---|---|
| 节点离线 | 检查代理服务 `systemctl status backup-center-agent` / macOS 的 launchd；确认网络到 150:8443 |
| 备份失败 | 看运行日志；常见为路径不存在、权限不足、仓库容量不足 |
| 目录看不到 | macOS 未授予完全磁盘访问；或路径不存在/无权限 |
| 恢复很慢 | 单文件恢复需下载对应数据块；大目录建议先下载 zip 或分批恢复 |
| 忘记密码 | 联系管理员重置（本地账号）或走 SSO |
