# TRI 集中备份平台（backup-center）项目文档

> 版本：v1.0　|　更新：2026-11-20
> 生产地址：**https://backup.tri.local**（旧域名 `https://eda.tri.local` 兼容）
> 部署主机：`172.16.50.150`（RHEL 8.10，hostname `eda`）
> 代码仓库：https://git.tri.local/it/backup.git

## 1. 项目概述

面向内网 Linux / macOS 服务器的**集中式文件备份平台**，以 restic 为备份引擎，提供 Web 管理、代理接入、审批、备份计划、时间点快照、文件级恢复、审计与告警。

目标能力：

- 代理安装后由管理员审批入网，通信全程 TLS，代理 API 强制 mTLS
- Web 上选择节点目录/文件，加入对应**备份池（存储库）**
- 首次全备 + 永久增量去重；zstd 压缩；AES-256 加密
- 按时间点浏览、下载、原地恢复；支持钉住（归档）与保留策略
- 一个节点可加入多个备份池；按池浏览/恢复
- Keycloak SSO：AD 组 `Group_Roots` 成员为管理员，其他员工只读
- 全量审计、容量看板、SMTP/Webhook 告警、仓库校验

## 2. 系统架构

```text
客户端（Linux systemd / macOS launchd）
  backup-agent（Go 静态二进制）
    ├─ 心跳/长轮询任务
    ├─ 文件系统浏览（只读）
    ├─ 执行 restic（备份/恢复/校验）
    └─ 内置 restic 0.18.0
        │ HTTPS 8443（mTLS，平台 CA）
        ▼
172.16.50.150
  backup-center（Node 24，零第三方运行时依赖）
    ├─ Web UI / 管理 API 443（Keycloak SSO / 本地应急 admin）
    ├─ Agent API + restic REST 数据面 8443（mTLS）
    ├─ 调度器 / 保留清理 / 校验 / 告警
    ├─ 快照浏览（restic ls）/ 下载（restic dump）/ 恢复任务
    └─ SQLite（node:sqlite）+ 主密钥加密敏感字段
        │ 本地 / NFS / CIFS / FTP（mountd）
        ▼
  /data2/backup/restic（默认池）、/data2/backup/projects 等
```

组件：

| 组件 | 技术 | 说明 |
|---|---|---|
| 管理端 | Node 24（`node:http/https/sqlite/crypto`） | 零 npm 运行时依赖 |
| 前端 | Vue 3 + Vite + Tailwind + ECharts | 构建产物在 `server/public` |
| 代理 | Go（仅标准库） | linux/amd64、darwin/arm64、darwin/amd64 |
| 备份引擎 | restic 0.18.0 | 仓库格式 v2、zstd 压缩、AES-256 |
| 挂载助手 | Go（root，Unix socket） | NFS/CIFS/FTP 挂载与本地目录授权 |
| 身份 | Keycloak（realm `tri`） | OIDC 授权码 + PKCE(S256) |

## 3. 功能与权限

| 能力 | 说明 |
|---|---|
| 节点接入 | 一次性 token（默认 60 分钟、单次使用）→ 审批 → 签发 1 年客户端证书（自动续期） |
| 多备份池 | 同一节点可写入多个存储库，`client_repo_keys` 按 (节点, 池) 保存独立仓库密码 |
| 目录选择 | Web 目录选择器浏览节点文件系统；禁止选择备份池自身，父目录自动排除池目录 |
| 计划调度 | 5 段 cron、备份窗口、压缩、上传限速、pre/post 钩子、并发限制 |
| 保留策略 | `keep-last/daily/weekly/monthly/yearly` 并集 + pinned；自动 prune（同池约 6 天一次） |
| 快照 | 按池列出时间点、目录浏览、文件名搜索、单文件/目录 zip 下载、钉住/删除 |
| 恢复 | 按池 + 时间点选择文件/目录 → 原地恢复（目标路径/覆盖策略/干跑） |
| 审计 | 登录、审批、计划、恢复、下载、删除等写操作落库 + JSONL |
| 告警 | 节点离线、备份失败、prune/check 失败、容量阈值；SMTP/Webhook |

角色：

| 角色 | 来源 | 权限 |
|---|---|---|
| admin | AD 组 `Group_Roots`（SSO）或本地应急 `admin` | 全部管理 |
| operator | 可分配 | 节点/计划/运行/恢复（默认不分配） |
| viewer | 其他 SSO 员工 | 只读查看/下载 |
| auditor | 可分配 | 只读 + 审计 |

## 5. 安全设计

- 传输：Web 443 TLS；Agent API/仓库 8443 **mTLS**；代理只出站，无监听端口。
- 证书：平台 CA 签客户端证书（1 年自动续期，序列号白名单）；服务端用企业通配证书。
- 仓库：每个 (节点, 池) 独立随机密码，AES-256-GCM 加密存库；数据面 append-only（仅允许删除 locks）。
- 权限：Keycloak groups/roles → admin/viewer；本地 admin 仅应急；RBAC 覆盖全部写接口。
- 审计：操作落 `audit_log` 与 `audit.jsonl`；恢复/下载可追溯。
- 主密钥离线托管要求见《灾难恢复》。

## 6. 备份与保留策略

- restic 模型：首次全备，之后永久增量去重；每个快照都是独立可恢复时间点。
- 推荐保留（每日一次）：`keep-last 7 / daily 30 / weekly 26 / monthly 24 / yearly 5` + pinned。
- `keep-monthly/yearly` 保留每个月/每年**最新**快照（通常月末/年末）；如需固定每月 1 日、1 月 1 日归档，请对这些快照**钉住**。
- 自动 prune：成功备份后按计划清理；同节点+同池约 6 天一次，`forget` 删引用、`prune` 释放空间。
- 容量：月度/年度快照只增加变化数据，不复制全量；仓库容量告警 75%/85%。

## 7. 恢复流程

1. 快照 → 选节点 → 选**备份池** → 选时间点；
2. 浏览目录、搜索文件、选择文件/目录；
3. 恢复向导：目标路径（`/` 为原位置）、覆盖策略、干跑；
4. 恢复任务查看进度/日志；恢复由在线代理执行，离线时用下载。

## 8. 运维要点

- 日常：`systemctl status`、`/healthz`、最近运行、容量、离线节点、校验结果。
- 保留/清理：同池 6 天节流；手动 `POST /api/clients/:id/prune`（可带 `repository_id`）。
- 校验：每周 `restic check`，每月 1% 读校验，结果在看板/告警。
- 备份自身：每日 03:00 复制 SQLite 到 `db-backups/`，保留 14 份。
- 故障：磁盘满、仓库锁、挂载失败、SELinux、证书过期等见《运维手册》。

- 生产环境完成：安装、SSO（Group_Roots=admin / 其他=viewer）、节点审批、全备/增量、多池备份、按时间点浏览/下载/恢复、审计、校验。
- 修复记录：REST 协议兼容、CA 链、多池 prune、审批中心数据、恢复 dry-run/SELinux xattr、接入命令内置企业根 CA 等。

## 10. 已知限制与后续

- 未做 Windows 客户端、镜像级备份、HA 多实例。
- 副本/异地容灾未内置 UI 作业，可手工 `restic copy` 或后续扩展。
- FTP 后端基于 rclone mount，建议优先 NFS/CIFS。
- macOS 正式安装需授予“完全磁盘访问”，批量分发可结合 MDM。
- 平台自身备份与主密钥离线下架需按 DR 手册执行。
