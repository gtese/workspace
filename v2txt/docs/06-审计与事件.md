# 06 · 审计与安全事件

## 模型

所有安全相关与用户关键操作都落一张只追加表 `audit_events`：

| 字段 | 说明 |
|---|---|
| `action` | 点分层级动作名，见下表 |
| `result` | `ok` / `fail` / `denied` |
| `org_id` / `user_id` / `actor` | 空间、用户 ID、可读身份（邮箱） |
| `ip` / `ua` | 取自 `X-Forwarded-For` / `CF-Connecting-IP`（经 Cloudflare 隧道传入） |
| `target` | 被操作对象（录音 ID、订单 ID、邮箱…） |
| `detail` | JSON 或文本（原因、变更前后值、参数） |
| `created_at` | UTC，索引 |

写审计失败**绝不影响业务**：`audit.record()` 内部吞异常并记日志。

## 已覆盖动作（31 个）

| 域 | 动作 |
|---|---|
| 认证 | `auth.register`、`auth.login`、`auth.login.failed`、`auth.logout`、`auth.email.verified`、`auth.password.forgot`、`auth.password.reset`、`auth.password.changed` |
| 飞书 | `auth.feishu.login`、`auth.feishu.failed` |
| 团队 | `org.create`、`org.rename`、`org.switch`、`org.invite`、`org.accept`、`org.role`、`org.member.remove` |
| 计费 | `billing.order.create`、`billing.order.cancel`、`billing.subscribe`、`billing.order.confirm`、`billing.grant` |
| 录音 | `recording.create`、`recording.upload`、`recording.delete`、`recording.rerun`、`recording.share.revoke`、`recording.share.restore`、`recording.email` |
| 运营 | `admin.user.status`、`admin.view` |

## 查询

运营后台 → 「事件日志」标签页，支持动作、结果、时间窗、关键字（邮箱/IP/目标/详情）过滤。

API（需 `FM_ADMIN_EMAILS` 权限）：

```
GET /api/v1/admin/events?action=auth.login.failed&result=fail&hours=168&q=1.2.3.4&limit=100
GET /api/v1/admin/events/summary?days=7
```

汇总返回：总数、按结果分布、独立用户数、独立 IP 数、Top 动作——用来快速发现暴破、盗链、异常付费。

## 保留期

默认 **180 天**，由维护线程 `cleanup_audit_events()` 随清理循环执行（`FM_RETENTION_CHECK_SECONDS`）。

## 与安全策略的配合

| 风险 | 现有控制 |
|---|---|
| 撞库/暴破 | 登录接口令牌桶限流（10 次/分，突发 3）+ `auth.login.failed` 审计（可按 IP 聚合） |
| 会话盗用 | 会话只存 SHA-256，可撤销；改密码自动踢全部会话 |
| 越权 | 所有业务接口按 `org_id` 校验成员关系，403；分享走 HMAC 签名 + 撤销表 + 访问审计 |
| 数据外泄 | 音频签名 URL 1 小时有效；分享链接 30 天且可撤销 |
| 运营误操作 | 订单确认、手工加额度、停用账号全部留痕（含操作人） |
| 审计被篡改 | 只追加、不提供更新/删除接口；运维只能通过 SQL 清理过期数据 |

## 数据库容量

当前：SQLite 单文件（`data/app.db`），WAL 模式，0.3 MB。

| 项 | 现状 | 上限参考 |
|---|---|---|
| 写入 | 单写者，WAL 下读不阻塞写；本地 NVMe 约数百次/秒简单写 | 日均万级事件无压力 |
| 数据量 | 录音 5 条、审计刚启用 | 1 万条录音（含转写 JSON）约 1–3 GB |
| 并发 | 单容器 + 2 个 worker 线程 | 10–20 个并发用户/任务流畅 |
| 全文检索 | `LIKE` 扫表 | 超过 1 万条录音后明显变慢 |

**什么时候换 Postgres**：

1. 需要跑多副本/多机（SQLite 只能单机单文件）
2. 并发写任务 > 3–5（单写者锁开始成为瓶颈）
3. 录音量 > 1 万条，或需要全文检索、按时间分区
4. 需要 PITR 备份与在线迁移

切换方式已预留：`docker compose --profile pg up -d db`，`.env` 设
`FM_DATABASE_URL=postgresql+psycopg://v2txt:<PG_PASSWORD>@db:5432/v2txt`，重启容器即可（表结构 `create_all` 自动建）。
