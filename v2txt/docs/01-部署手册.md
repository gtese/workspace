# 01 · 部署手册

## 目标环境

| 项 | 值 |
|---|---|
| 主机 | `172.16.50.166`（内网），出口 NAT `61.152.165.166` |
| 系统 | Ubuntu 24.04.5 LTS，8C / 7G / 48G |
| 容器 | Docker 29.10.0 + Compose v5.8.0 |
| 账号 | `user`（sudo 需密码，`~/.mm/v2txt-server` 保存） |
| 目录 | 项目 `/home/user/v2txt`，数据 `/home/user/v2txt/data` |
| 端口 | 宿主 `172.16.50.166:8080` → 容器 `8000` |

## 出口白名单（重要）

该机出口是**默认拒绝 + 白名单**，实测：

| 目标 | 结果 |
|---|---|
| `dashscope.aliyuncs.com`、`mirrors.aliyun.com`、`registry.cn-hangzhou.aliyuncs.com`、`pypi.org`、`smtpdm.aliyun.com` | ✅ 通 |
| `registry-1.docker.io`、`github.com`、`*.argotunnel.com`（Cloudflare）、`cas/dns.aliyuncs.com` | ❌ 不通 |
| 出口 25 / 465（SMTP） | ✅ 通 |

因此：
- 镜像来自内网搬迁（见下），不依赖 Docker Hub；
- apt 用 `mirrors.aliyun.com`，pip 用 `https://mirrors.aliyun.com/pypi/simple`；
- **Cloudflare 隧道必须让网管放行**：TCP 7844/UDP 7844 + 443 到 `region1.v2.argotunnel.com`、`region2.v2.argotunnel.com` 及 Cloudflare 隧道网段（`198.41.192.0/24`、`198.41.200.0/24`），以及 `api.cloudflare.com:443`（建隧道/证书）。

## 首次部署

```bash
# 1. 机房内已有基础镜像（python:3.12-slim / postgres:16-alpine / caddy:2-alpine）
docker images

# 2. 项目与配置
cd ~/v2txt
cp deploy/env.example .env && chmod 600 .env
vi .env          # 必改 FM_SECRET_KEY、FM_PUBLIC_BASE_URL、FM_ADMIN_EMAILS

# 3. 凭据（宿主机，绝不进仓库）
install -d -m 700 ~/.mm
#   ~/.mm/aliyun   ALIYUN_API_KEY=...  ALIYUN_BASE_URL=...
#   ~/.mm/smtp     SMTP_HOST/SMTP_PORT/SMTP_USER/SMTP_PASSWORD/SMTP_SENDER

# 4. 数据目录归属（容器以 uid 1000 运行）
mkdir -p data && sudo chown -R 1000:1000 data

# 5. 启动
docker compose build
docker compose up -d
curl -fsS http://172.16.50.166:8080/health
```

注册第一个账号后，把邮箱写进 `.env` 的 `FM_ADMIN_EMAILS` 并 `docker compose up -d --force-recreate`，即可访问 `/admin`。

## 镜像离线搬迁（docker.io 不可达时）

```bash
# 在有镜像的机器（旧服务器/笔记本）导出
podman save -q -o /tmp/i1.tar docker.io/library/python:3.12-slim
# 拷到新机后载入
docker load -i /tmp/i1.tar
```

注意：多个镜像一次 `podman save` 到一个 tar 时，`docker load` 可能把它当成同一个镜像打多个 tag，**必须逐个导出/载入**。

## Cloudflare Tunnel（待网络放行）

```bash
# 宿主机安装 cloudflared（二进制来自 GitHub，需先拷进来）
sudo install -m 755 cloudflared /usr/local/bin/cloudflared

cloudflared tunnel login                       # 浏览器授权，生成 ~/.cloudflared/cert.pem
cloudflared tunnel create v2txt                # 生成隧道 UUID 与凭据 json
cloudflared tunnel route dns v2txt app.v2txt.cn
cloudflared tunnel run --url http://127.0.0.1:8080 v2txt
# 固化：
sudo cloudflared service install <TUNNEL_TOKEN>
sudo systemctl enable --now cloudflared
```

域名前置条件：`v2txt.cn` 的 NS 必须指向 Cloudflare（当前在万网 `dns19/dns20.hichina.com`，需要在阿里云控制台改成 CF 分配的两条 NS）。Tunnel 的公开主机名只能建在 Cloudflare 托管的 zone 里，外站 CNAME 到 `cfargotunnel.com` 无效。

## 常用运维

```bash
cd ~/v2txt
docker compose ps                 # 状态
docker compose logs -f --tail=200 api
docker compose restart api
docker compose up -d --force-recreate   # 改了 .env 或挂载必须 force-recreate
make backup                       # 备份 DB + data 到 data/backups
```

健康检查：

- `GET /health` → `{"status":"ok","db_ok":true,"version":"2.0.0"}`
- `GET /api/v1/ops/health`（需 `X-Ops-Token`）→ 队列、磁盘、DB 指标

## 备份与恢复

- `python scripts/backup.py --out /app/data/backups --keep 14` 产出 sqlite + 音频清单压缩包。
- 恢复：停容器 → 解压覆盖 `data/` → 起容器。

## 排障清单

| 现象 | 原因 | 处理 |
|---|---|---|
| 容器 `Permission denied: /app/.mm` | `cap_drop ALL` 后 root 无法绕过 700 | 容器改以 uid 1000 运行（compose 已配 `user:`） |
| `Permission denied: /app/backend/...` | 源码文件权限 600 被打进镜像 | Dockerfile 已 `chmod -R a+rX /app`，本地保持 644 |
| ASR 报 `FILE_DOWNLOAD_FAILED` | 音频 URL 是内网地址，阿里云云端拉不到 | `FM_PUBLIC_BASE_URL` 必须是公网可达（隧道域名） |
| ASR 报 `缺少阿里云 MaaS 凭据` | 容器内 `/app/.mm/aliyun` 不存在/不可读 | 检查宿主 `~/.mm` 权限与 compose 挂载 |
| `docker compose` 报 `PG_PASSWORD missing` | 必填变量在解析期校验 | 用 `${PG_PASSWORD:-默认}` 或写进 `.env` |
