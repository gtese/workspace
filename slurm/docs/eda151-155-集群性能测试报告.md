## 五、结果分析

1. **151-155 五台性能完全一致**（同型号同配置）：单核整数 485 Mops / 浮点 424 Mflops，全核整数约 **48.7 Gops**，五台之间偏差 <0.2%，可直接作为一个统一规格计算池。
2. **单核性能**：151-155（485 Mops）比 131-133 虚拟机（393）**高约 23%**，约为 eda150（755）的 64%。EDA 工具多数单线程/低并行，新节点单核优势明显。
3. **全核吞吐**：151-155（112 核，≈48.7 Gops）略高于 131-133（128 vCPU，≈37.5 Gops）；eda150（384 核，≈240 Gops）是绝对吞吐王者（约为新节点的 4.9 倍）。
4. **内存子系统**：151-155 读写约 **13-15 GB/s**，明显优于 131-133（≈9-10 GB/s），约为 eda150（43-46 GB/s）的 1/3。但**内存容量/核比 ≈ 17 GB/核**（1900G/112核），是 150（≈1 GB/核）的 17 倍——**大内存 EDA 作业是新节点的核心优势**。
5. **磁盘 I/O**：eda150 NVMe 写 5.0 GB/s / 读 4.7 GB/s 最强；新节点 RAID 写约 **480 MB/s**、读 1.6~5.4 GB/s（读波动大，建议 fio 复核）；131-133 虚拟机写 114-215 MB/s / 读 240-310 MB/s 最弱。
6. **SHA256 单线程**：151-155 ≈960 MB/s > 131-133 ≈540 MB/s；150 ≈1683 MB/s，与单核 CPU 趋势一致。
7. **测试中发现并修复的隐藏问题**：trivm132 / trivm133 的 Slurm cgroup `cpuset` 根仍是历史遗留的 **0-15 / 0-31**（早期 16/32 核 VM 时创建，后来扩到 128 核但 cgroup 未更新），导致作业**最多只能用 16/32 核**。已修正为 0-127 并验证可跑满 128 核（本报告为修复后数据）。该问题对 131-133 上实际作业性能影响很大，建议写入巡检项。

## 六、结论与建议

- **151-155**：单核最强（x86 节点中）、内存容量巨大（1900G/台），适合 **EDA 大内存/长时作业** 和 **多用户并发**；本地磁盘写约 480 MB/s，适合临时数据，重 I/O 建议用 NAS/`/data`。
- **eda150**：多核吞吐与 I/O 最强，适合 **大规模并行 / 高 I/O** 作业。
- **131-133**：虚拟机，虚拟化有开销，且曾存在 cpuset 限制（已修复）；建议后续跑一次复核基准。
- **调度建议**：按内存需求优先把 EDA 作业调度到 151-155；MPI/高并行/高 I/O 作业给 150；131-133 作为轻量提交/交互节点。
