# 飞书录音纪要 · 需求与方案 v0.2

> 状态：需求对齐 3 轮；平台事实已核实（3 份调研报告见 `/tmp/feishu-minutes/`）。
> 关键变更：**入口由"小程序"改为"网页应用（H5）"**——飞书官方已将小程序标记为不再迭代，且 2025-01 起对未开发过小程序的企业逐步不允许创建入口。
> 更新：2026-11-20

## 1. 一句话产品

员工在飞书工作台打开「纪要录音」，在手机上开录（30–90 分钟会议），录完 1–5 分钟拿到**带时间戳、发言人分段、待办的结构化纪要**，自动推送飞书群、回调到公司网站、可选邮件发送。

## 2. 需求画像（3 轮问答结论）

| 维度 | 结论 |
|---|---|
| 核心场景 | 会议纪要、客户/一对一沟通归档、语音速记、长音频转文字 |
| 单次时长 | 30–90 分钟为主 |
| 转写 | 可上云，优先效果 |
| 敏感度 | 一般内部信息 |
| 输出去向 | 飞书群/机器人卡片、公司网站（只对接接口）、SMTP 邮件 |
| 实时性 | 录完再转，等 1–5 分钟可接受 |
| 说话人 | 能分出「发言人1/2」即可，不需要实名声纹 |
| 规模 | 10–50 人，5–20 场/天，月预算几百元 |
| 设备 | 手机放桌面 |
| 资源 | 2–4 核/8GB 无 GPU 服务器 + 域名；飞书管理员（应用未建）；无对象存储（用本地磁盘）；音频保留 30 天（2026-11-24 调整）、纪要永久 |

## 3. 五个关键判断

1. **入口必须是网页应用（H5），不是小程序。** 官方文档原文：「小程序将不再升级迭代，推荐选择网页应用能力」，且 2025-01-13 起对未开发过小程序的企业逐步不允许创建入口。工作台入口、免登、录音 JSAPI 在网页应用里都有。
2. **录音是"分段流水线"，不是"一条长录音"。** 官方录音 API `duration` 上限 600000ms（10 分钟），PC 端完全不支持录音；息屏/后台录音无任何官方保证。所以：手机前台 + 屏幕常亮 + 每 5 分钟一段 + 每段立刻上传。任何一段失败只重传该段。
3. **转写不必绕妙记。** 妙记 OpenAPI 上传只支持 user_access_token、且要先传到云空间（单文件 ≤20MB），链路长、还要吃企业 ASR 额度；直接调云端 ASR（腾讯/火山/阿里）更可控，单价可压到 0.29–0.8 元/小时。
4. **网站不重造。** 已有网站只做「菜单入口 + 回调接收 + 跳转详情页」，纪要正文/音频/搜索都在我们这边。
5. **纪要质量的上限是录音质量。** 手机放桌面 = 单麦远场，说话人分离只能到「发言人N」；产品上要降低预期（不绑实名），并给录音引导（居中放置、避开空调声、充电）。

## 5. 员工流程

1. 工作台点「纪要录音」→ 免登。
2. 选场景（会议 / 客户沟通 / 速记），填标题，可选客户、项目。
3. 点开始 → `setKeepScreenOn(true)`；每 5 分钟自动落一段并上传；界面显示"已录 27 分钟 / 3 段已上传 / 弱网重试中"。
4. 结束 → 合并转写中（可关页面）→ 1–5 分钟出纪要。
5. 飞书卡片：「纪要好啦」+ 摘要 + 待办 + 全文链接；操作：查看 / 确认归档 / 重新生成 / 转发。
6. 归档：推送指定群、回调公司网站、可选发邮件。

## 6. 功能清单

**P0**：免登；分段录音 + 断点续传；本地音频文件上传（wav/m4a/mp3/webm，ffmpeg 转码）；长音频异步转写（时间戳）；发言人分段；DeepSeek 纪要（摘要/要点/结论/待办）；三套模板；飞书卡片推送 + 确认归档；签名 URL 播放；失败重试与人工重转。

**P1**：网站回调 + 详情跳转（已实现）；SMTP 邮件（已实现，mock 可跑）；在线编辑/局部重新生成；说话人改名（已实现）；全文搜索（已实现）；术语表；使用统计与成本看板；30 天自动清理。

**P2**：实时字幕；从飞书日程自动建任务；待办同步飞书任务；方言/中英混说增强。

## 7. 技术选型（已定）

| 层 | 选择 | 依据 |
|---|---|---|
| 入口 | **飞书网页应用（H5）** | 小程序已停止迭代；H5 有同款录音 JSAPI |
| 前端 | 单页 H5（Vite + TS，轻量，无框架或 Preact） | 需要直连 JSAPI、控制录音生命周期 |
| 后端 | Python 3.12 + FastAPI + SQLAlchemy + Alembic | ASR/ffmpeg 生态 |
| 库 | PostgreSQL 16、Redis 7、RQ | 单机 Docker Compose 足够 |
| 存储 | 服务器本地磁盘 + HMAC 短时签名 URL | 无对象存储；抽象后易换 OSS |
| 转码 | ffmpeg：wav 16k 单声道合并 → m4a/AAC 供播放 | Android 只能 wav，浏览器播 AAC 最稳 |
| ASR | **腾讯云录音文件识别 大模型2.0（0.8 元/h）+ 会议引擎 16k_zh_en_meeting + 说话人分离**；备选火山豆包 2.0（0.8）；兜底阿里百炼 paraformer-v2（0.288） | 长音频 ≤5h、会议引擎、单价达标 |
| LLM | DeepSeek（deepseek-chat） | 中文纪要强、便宜 |
| 分发 | 飞书应用机器人 `im/v1/messages`；网站 REST 回调；SMTP | 研究 C：必须用应用机器人，自定义 webhook 不支持单聊/回调 |
| 部署 | Docker Compose + Caddy（HTTPS） | 已有服务器 |

> 飞书官方"妙记 OpenAPI"作为备选路线保留（上传→妙记→导出转写），不用于 v1。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| H5 录音能力不确定（getUserMedia 官方无记载） | POC-1 先真机验证；双通道：JSAPI recorder 优先，getUserMedia 兜底；再不行转"系统录音机录 → 网页上传" |
| 10 分钟硬上限 | 5 分钟自动分段 + 每段立即上传，页面显示分段进度 |
| 息屏/来电中断 | 屏幕常亮 + 录前提示"别锁屏"；中断自动续录新段，已传段不丢 |
| 手机单麦远场音质 | 录音引导卡片；ASR 选会议引擎；说话人不绑实名 |
| 腾讯 0.8 元/h 可能是推广价 | 接两家 ASR 适配器，按量比价切换 |
| 飞书应用审核 | 先用体验版与受限可用范围；scope 按最小集申请 |
| 本地磁盘满 | 90 天清理 + 容量监控 + 存储抽象可换 OSS |

## 11. 下一步（需要你做的）

1. 在飞书开放平台创建企业自建应用（名称建议「纪要录音」），开启**网页应用**能力，记下 App ID / App Secret。
2. 申请权限：`im:message:send_as_bot`、`docx:document`（可选）、`contact:user.base:readonly`、`authen:user.id:read`；网页应用需配置安全域名与 JSAPI。
3. 开通腾讯云语音识别（免费 10h/月）或火山（免费 20h/半年），拿 SecretId / SecretKey。
4. 提供服务器 SSH 访问方式与域名计划（用于 HTTPS 部署）。

凭据统一放 `~/.mm/feishu-minutes`（飞书）、`~/.mm/tencent-asr`（腾讯）、`~/.mm/server`（服务器），不要贴聊天里。
