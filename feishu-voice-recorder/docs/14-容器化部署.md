# 容器化部署与迁移（Podman Compose）

> 目标：用一份 `.env` 传参（域名、端口、API Key、保留期等），换机器只改配置即可启动。
> 当前生产服务器为 Rocky 8 + Podman 4.9 + podman-compose，未安装 Docker。

## 1. 架构

```
主机端口 5266
  └─ caddy（TLS 终止 / gzip / 访问日志）
       └─ api（uvicorn 8000，FastAPI + worker 线程）
            └─ ./data → /app/data（SQLite、m4a、outbox）
  events（同一镜像，飞书 WebSocket 长连接）
可选：db（Postgres 16，`docker-compose.postgres.yml` overlay）
```

- 不监听 80/443，避免与主机 nginx 冲突。
- 数据、证书、`~/.mm` 凭据全部以卷/只读挂载进入容器。

## 2. 快速启动（新机器）

```bash
git clone <repo> feishu-voice-recorder && cd feishu-voice-recorder
cp deploy/env.example .env && chmod 600 .env
$EDITOR .env                 # 至少改 DOMAIN、FM_PUBLIC_BASE_URL、FM_SECRET_KEY
mkdir -p data deploy/certs
cp -r ~/.mm ./mm-placeholder # 仅示意；实际用 MM_DIR 指向 ~/.mm，见下
make build
podman-compose up -d
curl -k https://<domain>:5266/health
```

> 凭据挂载使用 `$HOME/.mm`；用 rootful podman 时请设置 `HOME=/home/<user>` 再启动。
> 首次启动前把证书放进 `deploy/certs/`（`fullchain.pem`、`privkey.pem`）。

### mock 模式（无凭据、离线验证）

`.env` 里设置：

```
FM_ASR_PROVIDER=mock
FM_LLM_PROVIDER=mock
FM_FEISHU_MODE=mock
FM_PUBLIC_BASE_URL=http://127.0.0.1:5266
```

`make up` 后可完整走通录音 → 转写 → 纪要（不产生真实费用）。

## 3. 配置项

| 变量 | 说明 | 示例 |
|---|---|---|
| `DOMAIN` | 对外域名（Caddy 用） | `voice.example.com` |
| `PORT` | 对外端口，默认 5266 | `5266` |
| `FM_PUBLIC_BASE_URL` | 生成链接/回调用的根地址 | `https://voice.example.com:5266` |
| `FM_SECRET_KEY` | 会话/签名密钥，必须随机长串 | `<redacted>` |
| `HOME`（运行环境） | 凭据目录取 `$HOME/.mm` | `/home/<user>` |
| `FM_ASR_PROVIDER` | `mock` / `aliyun` / `aliyun_filetrans` / `tencent` | `aliyun_filetrans` |
| `FM_LLM_PROVIDER` | `mock` / `aliyun` / `deepseek` | `aliyun` |
| `FM_FEISHU_MODE` | `mock` / `real` | `real` |
| `FM_WORKER_COUNT` | 并发 worker 数 | `2` |
| `FM_RETENTION_DAYS` | 音频保留天数 | `30` |
| `FM_OPS_TOKEN` | 运维接口 token | 随机串 |
| `FM_ALERT_OPEN_IDS` | 告警接收人 open_id（逗号分隔） | `ou_xxx` |
| `FM_DATABASE_URL` | 默认空 = SQLite；Postgres 见 overlay | — |

凭据优先级：环境变量 > `~/.mm/<服务名>` 文件。容器内 `HOME=/app`，`~/.mm` 挂载为 `/app/.mm:ro`。

## 4. TLS 证书

- 证书目录：`deploy/certs/fullchain.pem`、`deploy/certs/privkey.pem`（权限 0600）。
- 续期仍由主机 certbot（DNS-01）负责；续期后执行：

```bash
cp /etc/feishu-minutes/tls/fullchain.pem deploy/certs/
cp /etc/feishu-minutes/tls/privkey.pem  deploy/certs/
podman exec trace-voice_caddy_1 caddy reload --config /etc/caddy/Caddyfile
```

- 建议把上述命令写进 `/opt/acme/renew-hook.sh`，实现自动续期加载。
- 若暂时没有证书：可先用 `openssl req -x509 -newkey rsa:2048 -nodes -days 30 -subj "/CN=<domain>"` 自签验证，再换正式证书。

## 5. 数据与迁移

```bash
# 旧机导出
rsync -a /opt/feishu-minutes/data/ ./data/
cp /etc/feishu-minutes/tls/* deploy/certs/
# 新机导入后
podman-compose up -d
```

- SQLite：`./data/app.db`；音频：`./data/recordings/`（m4a）。
- 迁移前建议 `make backup`；迁移后校验：
  `sqlite3 data/app.db "pragma integrity_check;"` 与文件数。
- 升级：`make build && make up`（数据卷不变）。

## 6. 备份与清理

```bash
make backup          # 调用 scripts/backup.py，输出到 ./data/backups
make logs            # 查看 api/events/caddy 日志
make ps              # 容器状态
```

- 音频 30 天自动清理（应用内 + 主机 cron 均可）。
- 每日主机 cron 示例：
  `0 4 * * * cd /path/feishu-voice-recorder && podman-compose exec -T api python scripts/cleanup.py`

## 7. 回滚（保留 systemd 方案）

```bash
podman-compose down
sudo systemctl start feishu-minutes feishu-events
```

切换前 systemd 服务保持原样、数据目录未动，回滚 5 分钟内完成。

## 8. 生产更新流程

```bash
# 开发机：提交后同步代码到栈目录（不要覆盖 data/.env/certs）
rsync -a --exclude data --exclude .env --exclude 'deploy/certs/*.pem' \
  ./ <user>@<host>:/home/<user>/fvr/

# 服务器：重建镜像并滚动重启
cd ~/fvr
podman-compose build api
podman-compose up -d
podman-compose logs -f --tail=50
```

- `events` 与 `api` 共用同一镜像，`up -d` 会一并更新。
- 生产栈目录当前为 `/home/linyiyao/fvr`；旧 systemd 单元保留可回滚。

## 9. 故障排查

| 现象 | 处理 |
|---|---|
| `setgroups ... Operation not permitted` | 给用户加 subuid：`sudo usermod --add-subuids 100000-165535 --add-subgids 100000-165535 $USER && podman system migrate` |
| 卷权限/SELinux 拒绝 | 确认挂载带 `:Z`；`sudo ausearch -m avc -ts recent` 查看 |
| 拉不到 caddy 镜像 | 配置 `/etc/containers/registries.conf` 镜像加速，或临时用主机 nginx/uvicorn TLS |
| 健康检查失败 | `podman logs <api容器>`；确认 `.env` 中 `FM_DATA_DIR=/app/data` |
| 证书未生效 | `podman exec <caddy> caddy validate --config /etc/caddy/Caddyfile` 后 reload |
