# 开发与部署

## 本地跑通（全程 mock，无需任何凭据）

```bash
cd feishu-minutes
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt

cd backend
FM_SYNC_PIPELINE=true ../.venv/bin/python -m uvicorn app.main:app --port 8000 --reload
```

打开 <http://127.0.0.1:8000/>：桌面浏览器里点「开始录音」会请求麦克风权限；
录一小段 → 结束 → 页面上能看到转写（mock 文本）和纪要。

> 手机上要真机测试，需要 HTTPS 公网地址（getUserMedia 要求安全上下文）。
> 把 `FM_PUBLIC_BASE_URL` 设为公网地址，再用 `deploy/` 里的 Caddy 或任意隧道工具暴露。

## 飞书网页应用免登

流程与官方示例一致：

1. 页面加载飞书 H5 JSSDK（`h5-js-sdk`）。
2. `window.h5sdk.ready()` 后调 `tt.requestAccess({ appID, scopeList: [] })`（旧版 `tt.requestAuthCode` 作兜底）拿 `code`。
3. 前端 `POST /api/v1/auth/feishu-login {code}` → 服务端用 `app_access_token` 换 `user_access_token`，再取 `open_id`。
4. 服务端签发自有会话 token（`fm_...`，7 天有效），前端存 localStorage，后续请求带 `Authorization: Bearer fm_...`。
5. 未配置真实应用时（`FM_FEISHU_MODE=mock`），登录接口返回 mock 身份 `demo`，页面照常可用。

> 必须在开发者后台 **安全设置 → 重定向 URL** 里配置页面 URL（不含 query 与 hash），否则 `requestAuthCode` 会报 10236。

## 分享与转发

- 详情页「复制分享链接」→ `GET /api/v1/recordings/{id}/share` 返回 30 天签名链接；
  匿名打开 `/s/<id>?exp&sig` 只读（无登录），接口为 `GET /api/v1/shared/{id}`。
- 转发到飞书会话：`POST /api/v1/recordings/{id}/send`，body `{receive_id, receive_id_type}`，
  默认发给自己；mock 模式落盘 `data/outbox/`。

## 说话人与搜索

- 改名：`PUT /api/v1/recordings/{id}/speakers`，body `{"mapping": {"发言人1": "张三"}}`；
  映射存 `speaker_names` 表，显示时套用；重跑纪要时以真实姓名喂给 LLM。
- 搜索：`GET /api/v1/search?q=关键词`，检索当前用户录音的标题/转写/纪要，返回 50 条带片段。

## 备份与回收

```bash
cd backend
../.venv/bin/python scripts/backup.py --out /data/backups --keep 14
```

- SQLite 用 `sqlite3 backup` 在线备份（不锁库），PostgreSQL 用 `pg_dump -Fc`
- 一起打包 `data/recordings`，输出 `fm-backup-<时间戳>.tar.gz`，自动保留最近 N 份
- 启动时回收没有数据库记录、超过 1 天的孤儿录音目录（异常中断残留）

## 弱网与前台保活

- 屏幕常亮：优先用浏览器 Wake Lock API（`navigator.wakeLock`），切回前台自动重新申请。
- 麦克风电平：`AnalyserNode` 实时显示音量，方便确认录音正常。
- 上传失败：分段音频保留在内存并显示「重试上传本段」，网络恢复后直接续传，不用重录。
- 权限错误：NotAllowedError / NotFoundError / NotReadableError 分别给中文提示。

## 断点续录

录音页会把当前 `recording_id` 存在 localStorage；刷新/重开后如果该录音仍是
`recording` 状态，顶部提示「继续录音」，从 `next_segment_index` 继续上传，已传段落不受影响。

## 后台任务与清理

- **队列 worker**：`app/worker.py` 每 2 秒从数据库取 `queued` 任务串行处理，进程重启不丢任务；
  启动时把停在 `transcribing/summarizing` 的任务重新排队。
- **邮件**：录音本人有邮箱时，纪要归档后发 HTML 邮件；`FM_EMAIL_MODE=mock`（默认）只落盘到 `data/outbox/`，方便联调。
- **音频保留**：`app/maintenance.py` 启动时 + 每 6 小时清理超过 `FM_RETENTION_DAYS`（默认 90 天）的音频与分段，
  转写和纪要正文永久保留。

## 音频格式与转码

- 浏览器录音统一编码为 16k 单声道 WAV（无需转码）。
- 兜底上传支持 m4a/mp3/webm/wav：服务端用 ffmpeg 转 16k 单声道 WAV。
- ffmpeg 查找顺序：系统 `ffmpeg` → `imageio-ffmpeg` 自带二进制（本地开发用，见 `backend/requirements-dev.txt`）。
- 容器里已装系统 ffmpeg（Dockerfile）。

## 切真实服务

| 变量 | 值 | 凭据位置 |
|---|---|---|
| `FM_ASR_PROVIDER` | `tencent` | `~/.mm/tencent-asr` |
| `FM_LLM_PROVIDER` | `deepseek` | `~/.mm/deepseek` |
| `FM_FEISHU_MODE` | `real` | `~/.mm/feishu-minutes` |
| `FM_WEBSITE_CALLBACK_URL/SECRET` | 公司网站回调 | `~/.mm/website-callback` |
| `FM_EMAIL_MODE=real` | 邮件 SMTP 发送 | `~/.mm/smtp` |

凭据文件格式：`KEY=VALUE` 每行一条，权限 0600。

## 生产部署（Docker Compose）

```bash
cp .env.example .env   # 填 DOMAIN、FM_PUBLIC_BASE_URL、POSTGRES_PASSWORD 等
docker compose up -d --build
```

- `api`：FastAPI（含 ffmpeg，供 M2 转码用）
- `db`：PostgreSQL 16
- `caddy`：自动 HTTPS，反代到 api
- 数据：`./data`（音频）、`pgdata`（数据库）

## 已知限制（POC 阶段）

- 流水线用后台线程，进程重启会中断 → M2 换 Redis/RQ。
- 只接受 WAV 分段；浏览器端已统一编码为 16k 单声道 WAV。
- 飞书免登未接：当前用 `X-Employee-Open-Id` 头模拟身份（默认 demo）。
- 详情页 `/d/{id}` 的 open_id 取 `localStorage.fm_uid`，默认 demo。
