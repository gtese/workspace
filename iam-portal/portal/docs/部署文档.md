# 企业应用门户（portal.tri.local）

员工登录公司统一身份后，在这里看到**自己能用的所有系统**，点一下即进入。
不再是"记住四个网址、每个系统各登一次"。

| 项 | 值 |
|---|---|
| **访问地址** | **https://portal.tri.local** |
| 部署主机 | `trivm122.tri.local`（172.16.50.122） |
| 技术栈 | Node.js 20（**零第三方依赖**）+ nginx 反代，容器端口 `127.0.0.1:8095` |
| 登录方式 | 公司统一身份 `sso.tri.local`（OIDC，授权码 + PKCE S256） |
| 会话 | 本站 HttpOnly Cookie（8 小时），令牌不落浏览器 |
| 版本 | 1.1.0（2026-11-04：应用列表可视化编辑 + 拖拽排序） |
| 验收 | 登录链路 **12/12**；编辑功能 **10/10** |

## 1. 员工怎么用

```
员工浏览器 ──①打开 portal.tri.local──▶ 门户（未登录自动跳统一身份）
            ②在 sso.tri.local 输一次域账号口令
            ③回到门户，看到应用列表
            ④点卡片进入系统（已接入统一身份的系统免登录）
            ⑤右上角「退出」→ 结束门户会话并跳统一身份登出
```

**员工手册口径**：

- 打开 <https://portal.tri.local>，用公司域账号登录一次；
- 之后的 8 小时内，门户里的应用都可以直接点进去；
- 标记「**免登录**」的应用，点进去不需要再输口令；
- 标记「**需单独登录**」的应用还没接入统一身份，进去仍需输一次域账号（在逐步改造）；
- 标记「**即将上线**」的应用还没部署好；
- 用完后点右上角「退出」。如果要在所有系统都退出，请在统一身份页面确认退出。

> 目前应用列表：企业 AI 助手（chat）、科研项目职能支持（work）、代码仓库（GitLab）、
> 集群作业管理（slurm，指向 **Open OnDemand** https://edas.tri.local，已接 SSO）。

### 调整应用列表的两种方式

| 方式 | 适用 | 操作 |
|---|---|---|
| **页面编辑（推荐）** | 日常微调、排序、改文案 | 管理员登录后点右上角 **✏️ 编辑** → 拖动/修改 → 保存（立即生效，无需重启） |

> **优先生效，会覆盖代码里的默认值**；改完代码默认值后用「恢复默认」按钮同步到页面。

## 4. 部署（首次）

```bash
# 在 172.16.50.122 上（root 的 podman）
git clone <repo> /opt/tri-portal && cd /opt/tri-portal

cp deploy/.env.example deploy/.env
vi deploy/.env      # 填 OIDC_CLIENT_SECRET（从 sso.tri.local 取）
chmod 600 deploy/.env

cp /etc/pki/tls/certs/tri.local_ca.crt deploy/certs/   # 企业根 CA（烤进镜像用）

./deploy/deploy.sh build      # 构建镜像
./deploy/deploy.sh up         # 启动容器
./deploy/deploy.sh nginx      # 安装 nginx 站点（需 sudo）
python3 deploy/scripts/verify.py <域账号> <口令>   # 验收 12 项
```

**IdP 侧**（在 sso.tri.local 主机上）：client `portal` 已由 `configure.py` 创建，
回调白名单 `https://portal.tri.local/*`，已分配 `roles` + `groups` scope。

## 4.5 门户编辑功能（v1.1.0）

| 功能 | 操作 | 说明 |
|---|---|---|
| 拖动排序 | 编辑面板里拖左侧 `⠿` 手柄 | 鼠标/触屏都支持；松手后立即看到新顺序 |
| 编辑卡片 | 点「编辑」 | 改名称、说明、地址、图标、分组、各种标记（免登录/新标签/即将上线/仅管理员/公开/隐藏） |
| 新增卡片 | 点「＋ 新增应用」 | ID 留空自动生成 |
| 删除卡片 | 点「删除」 | 只从门户移除，不影响系统本身（有二次确认） |
| 隐藏/显示 | 点「隐藏」 | 隐藏的卡片员工看不到，但配置保留 |
| 恢复默认 | 点「恢复默认」 | 回到 `src/apps.js` 的出厂列表；**当前配置会先备份** |
| 保存 | 点「保存」 | 写入 `portal-config.json` 并立即生效 |

**权限**：只有持有任意 `*:admin` 业务角色（如 `kb:admin`，对应 AD 组 `Group_Roots`）的人能看到「编辑」按钮，
且服务端每个写接口都二次校验角色，前端隐藏不等于放行。

**安全校验**：地址必须是 `https`；名称不能为空；ID 只允许字母数字下划线短横线；应用至少要保留一个。

**备份**：每次保存/重置都会在数据卷 `/app/data/backups/` 留一份历史（保留最近 30 份），误操作可找回。

**未登录行为**：
- 应用里**有**「公开」标记的卡片 → 未登录也展示（点进去再登录）；
- 全都不是公开 → 未登录直接 302 到统一身份（打开即登录）。

## 5. 运维

```bash
./deploy/deploy.sh status     # 容器状态 + 健康检查 + 站点探测
./deploy/deploy.sh logs       # 实时日志
./deploy/deploy.sh update     # ★ 改了 apps.js 后：重建镜像并重启
systemctl restart tri-portal.service   # 重启（已注册开机自启）
```

| 项 | 位置/方式 |
|---|---|
| 开机自启 | `/etc/systemd/system/tri-portal.service`（已 enable） |
| 健康巡检 | `/etc/cron.d/tri-portal-health`，每 5 分钟 → `/var/log/tri-portal-health.log` |
| 日志 | `podman logs tri-portal`（journald）；nginx 在 `/var/log/nginx/portal.*.log` |
| 密钥 | `/opt/tri-portal/deploy/.env`（600，不入库） |
| 回滚 | 镜像与容器独立，`podman-compose down` 即停；不影响任何业务系统 |

## 7. 设计取舍与已知限制

| 项 | 现状 | 说明 |
|---|---|---|
| 会话存储 | 进程内存 | 单实例够用；多实例需换 Redis（`session.js` 接口不变） |
| 免二次点击 | 依赖 IdP 会话（8h idle / 24h max） | 下午 IdP 会话过期后，从门户点应用需重新输一次口令 |
| 「退出」范围 | 门户 + IdP 会话 | 各业务系统自己的会话（如 chat 的 4 周 JWT）仍在，**这是当前架构的已知限制** |
| 应用顺序/分组 | 页面可视化编辑（存 `portal-config.json`） | 想按部门/角色收敛，用「仅管理员」标记或扩展 `visibleApps()` |
| 编辑并发 | 单人编辑，无冲突检测 | 两人同时保存时后保存者覆盖；保存前会留备份 |
| slurm | ✅ 指向 Open OnDemand（https://edas.tri.local，已接 SSO） | 2026-11-09 更新 `src/apps.js` 并 `./deploy/deploy.sh update` |
| 门户用量统计 | 无 | 如需看"谁在用什么"，在 `/api/apps` 里加埋点（未做） |
