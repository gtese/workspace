# 门户运维速查

| 我要做的事 | 操作 |
|---|---|
| 看门户是否正常 | `curl -s http://127.0.0.1:8095/healthz`（返回 `{"ok":true,...}`） |
| 看站点是否正常 | `curl -sk -o /dev/null -w '%{http_code}\n' https://portal.tri.local/`（302 表示未登录跳转，正常） |
| 改应用列表（推荐） | 管理员登录门户 → 右上角 **✏️ 编辑** → 改完点保存（立即生效） |
| 改应用列表（代码默认） | 改 `/opt/tri-portal/src/apps.js` → `cd /opt/tri-portal && ./deploy/deploy.sh update` |
| 看谁改过配置 | `podman exec tri-portal cat /app/data/portal-config.json \| head -5`（含 `updatedBy`/`updatedAt`） |
| 找历史配置（误操作恢复） | `podman exec tri-portal ls /app/data/backups/`（保留最近 30 份） |
| 恢复历史配置 | 把备份文件拷成 `portal-config.json` 后 `podman restart tri-portal` |
| 恢复出厂配置 | 管理员在编辑面板点「恢复默认」 |
| 重启 | `systemctl restart tri-portal.service` |
| 看日志 | `podman logs -f --tail 100 tri-portal` |
| 看 nginx 日志 | `tail -f /var/log/nginx/portal.error.log` |
| 看健康巡检 | `tail /var/log/tri-portal-health.log`（只写异常） |
| 轮换 client secret | IdP 侧改 `OIDC_CLIENT_SECRET_PORTAL` → `deploy.sh provision`；门户侧改 `.env` → `deploy.sh update` |
| 停用门户 | `systemctl stop tri-portal && systemctl disable tri-portal`（不影响任何业务系统） |
| 门户打不开但容器正常 | 检查 nginx：`nginx -t`；SELinux：`getsebool httpd_can_network_connect` 应为 on |

## 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 点登录后回门户报「统一身份校验失败」 | 看 `podman logs tri-portal` 的 `callback failed:` 行；常见为 IdP client secret 不一致 |
| 门户首页一直跳登录页 | 浏览器禁用了 Cookie；或系统时间偏差过大导致会话立即过期 |
| 应用卡片点进去要重新登录 | 该应用未接入统一身份（卡片上标「需单独登录」），属预期 |
| slurm 卡片点不开 / 地址不对 | 已指向 Open OnDemand（https://edas.tri.local），如仍显示占位卡，管理员进编辑面板取消「即将上线」；或运行 `./deploy/deploy.sh update` |
| `deploy.sh` 报 `profile: command not found` | `.env` 里 `OIDC_SCOPE` 没加引号（值含空格）；改为 `OIDC_SCOPE="openid profile email roles groups"` |
| 看不到「✏️ 编辑」按钮 | 当前账号没有 `*:admin` 业务角色（如 `kb:admin`，对应 AD 组 Group_Roots） |
| 编辑后刷新变回去了 | 点了「取消」或没点「保存」；保存失败会弹红色提示 |
