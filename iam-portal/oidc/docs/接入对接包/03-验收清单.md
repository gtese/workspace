# 03 验收清单（上线前必须全过）

> 用法：复制到你们的交付单/工单里，逐条打勾并**记录实测人+时间**。
> 标 🔴 的是"不过就不许上线"的项。
> 每条都写了「怎么测」和「失败看哪里」。

---

## A. 登录主链路

| # | 用例 | 怎么测 | 期望 | 失败看哪 |
|---|---|---|---|---|
| A1 🔴 | 未登录跳转 | 浏览器无痕窗口打开系统首页 | 自动跳到公司统一登录页（地址栏 `sso.tri.local`） | 地址栏 `error_description`；后端日志 |
| A2 🔴 | 深链接回跳 | 直接打开 `/某个需要登录的页面` 发起登录 | 登录后回到该页面（不是回首页） | `returnTo`/`state` 是否保存并回传 |
| A3 🔴 | 正常登录 | 输入域账号 + 口令 | 进入系统，显示正确姓名/邮箱 | ID Token 的 `sub`/`name` |
| A4 🔴 | 错误口令 | 故意输错 | 提示"账号或口令错误"类信息（**不暴露账号是否存在**） | IdP 日志 `LOGIN_ERROR` |
| A5 | 登录取消 | 在 IdP 页点返回/关闭 | 回到系统且**不报 500**（友好提示） | 是否处理了无 `code` 的回调 |
| A6 | 重复使用 code | 同一 code 换两次令牌 | 第二次 400 `invalid_grant` | — |
| A7 | state 被篡改 | 手动改回调 URL 里的 `state` | 400 拒绝，不建立会话 | 是否真的校验 state |

## B. 身份与会话

| # | 用例 | 怎么测 | 期望 | 失败看哪 |
|---|---|---|---|---|
| B1 🔴 | 用户主键是 `sub` | 查库或日志看新建用户的标识 | 以 UUID（`sub`）关联，不是用用户名做外键 | 建会话逻辑 |
| B2 🔴 | Cookie 属性 | 浏览器开发者工具 → Application → Cookies | 有 `HttpOnly`、`Secure`、`SameSite=Lax` | — |
| B3 🔴 | 令牌不下发浏览器 | 查看响应头/前端存储 | 前端无 access_token/id_token；localStorage 为空 | — |
| B4 | 会话时长 | 空闲 8 小时后访问 | 要求重新登录（或与你系统约定一致） | — |
| B5 | 多标签页 | 开 5 个标签，其中一个退出 | 其余标签下次请求后跳登录（不出现空白/死循环） | 401 处理逻辑 |
| B6 | 老用户对账 | 用改造前就在系统里的员工登录 | 历史数据（如果他/她是作者/负责人）仍然正确关联 | 首次对账是否按 `preferred_username` 绑定 |

## C. 授权（权限没有被放宽）

| # | 用例 | 怎么测 | 期望 |
|---|---|---|---|
| C1 🔴 | 普通员工 | 用普通账号登录 | 只能看到普通功能，**看不到管理员/审核/财务入口** |
| C2 🔴 | 管理员 | 用管理员账号登录 | 对应管理功能可用 |
| C3 🔴 | 越权直连 | 普通账号直接请求管理接口（curl） | 返回 403，**不是**只在前端隐藏 |
| C4 | 撤权生效 | IT 把测试账号移出角色对应 AD 组 → 重新登录 | 权限消失（下次登录/刷新后） |
| C5 | 离职立即失效 | IT 在 AD 禁用测试账号 | 下一次登录被拒；已登录会话到期后失效 |
| C6 🔴 | 依赖 AD 组的系统 | 若你的系统用 `groups`：检查部门/项目范围 | 部门成员仍能看到本部门内容；未分部门的人看不到部门内容 |

## D. 登出（单点登出）

| # | 用例 | 怎么测 | 期望 |
|---|---|---|---|
| D1 🔴 | 本地登出 | 点退出 | 回到登录页 |
| D2 🔴 | 跨系统登出 | 登录 A 系统 + 本系统 → 在本系统退出 → 再打开 A 系统 | A 系统要求重新登录 |
| D3 | 退出后返回 | 退出后按浏览器"后退" | 不应出现已登录内容（缓存页也要处理） |

## E. 故障与边界

| # | 用例 | 怎么测 | 期望 |
|---|---|---|---|
| E1 🔴 | IdP 不可用 | IT 临时停掉一个 IdP 实例 | 用户仍能登录（双实例）；两实例都停时**拒绝登录**，而不是放行 |
| E2 🔴 | 旧登录已关闭 | `curl -X POST /旧登录接口` | 404/405，**不能**用口令登录绕过 |
| E3 | 时钟偏差 | 与 NTP 对齐前提下测试 | 无 `令牌尚未生效` 类错误 |
| E4 | 多次快速点击登录 | 连点 5 次 | 不产生多个会话/异常 |

## F. 浏览器与终端

| # | 用例 | 期望 |
|---|---|---|
| F1 🔴 | Safari（Mac 主力浏览器） | 无证书警告、登录正常、无"登录循环" |
| F2 🔴 | Chrome | 同上 |
| F3 | Mac 合盖唤醒后 | 不出现白屏/无限跳转；过期则回登录页并**回到原页面** |
| F4 | 企业根证书 | 若提示证书不受信，说明 Mac 未装 `tri.local_ca.crt`（不是接入问题） |

## G. 文档与交接

| # | 项 | 要求 |
|---|---|---|
| G1 | 变更记录 | 写清：切换时间、回滚方式（`AUTH_MODE` 开关）、谁执行 |
| G2 | 回滚演练 | 实际演练一次切回旧登录（可在测试环境）并能恢复 |
| G3 | 运维交接 | 你的同事知道：账号问题找 HR/IT，登录报错先看地址栏 `error_description` |
