# 02 参数与接口（照抄即可）

> 所有 URL 固定，除非本文写明可变。`<…>` 处替换成你自己的值。
> 频率/有效期以 IdP 实际配置为准，需要改找 IT。

## 1. 连接参数

| 项 | 值 |
|---|---|
| Issuer | `https://sso.tri.local/realms/tri` |
| Discovery | `https://sso.tri.local/realms/tri/.well-known/openid-configuration` |
| 授权端点 | `https://sso.tri.local/realms/tri/protocol/openid-connect/auth` |
| 令牌端点 | `https://sso.tri.local/realms/tri/protocol/openid-connect/token` |
| UserInfo | `https://sso.tri.local/realms/tri/protocol/openid-connect/userinfo` |
| JWKS | `https://sso.tri.local/realms/tri/protocol/openid-connect/certs` |
| 登出端点 | `https://sso.tri.local/realms/tri/protocol/openid-connect/logout` |
| Client 类型 | **Confidential**（有后端）；无后端只能用 Public + PKCE，需 IT 审批 |
| PKCE | **必须 S256** |
| 签名算法 | RS256 |
| TLS | 用内网企业根 CA `tri.local_ca.crt` 校验（不要关校验） |

**scope**

| scope | 用途 | 备注 |
|---|---|---|
| `openid` | 必填 | |
| `profile` | 姓名（`name`） | |
| `email` | 邮箱 | |
| `roles` | 业务角色（`realm_access.roles`） | **权限判断都用它** |
| `groups` | AD 组（userinfo 里的 `groups`） | 仅在"权限依赖 AD 组"时使用；需 IT 为你的 client 分配 |

## 2. 授权请求（浏览器整页跳转）

```
GET https://sso.tri.local/realms/tri/protocol/openid-connect/auth
    ?client_id=<CLIENT_ID>
    &redirect_uri=<已登记的回调地址，例如 https://myapp.tri.local/auth/callback>
    &response_type=code
    &scope=openid%20profile%20email%20roles
    &state=<随机，≥16 字节>
    &nonce=<随机，≥16 字节>
    &code_challenge=<BASE64URL(SHA256(code_verifier))>
    &code_challenge_method=S256
```

- 成功后 302 到 `redirect_uri?code=...&state=...&session_state=...`
- 失败时 302 到 `redirect_uri?error=...&error_description=...&state=...`（**先看地址栏**）

常见 `error_description`：

| error | 含义 | 处理 |
|---|---|---|
| `Invalid parameter: redirect_uri` | 回调地址与登记值不一致 | 逐字符核对（斜杠、http/https、域名） |
| `Invalid scopes: ...`（invalid_scope） | client 没有该 scope | 找 IT 分配 `roles` / `groups` |
| `Client not found` | clientId 拼错或未启用 | 找 IT |
| `Missing parameter: code_challenge_method` | 没带 PKCE | 补 `code_challenge` 与 `S256` |

## 3. 令牌请求（后端 ↔ IdP）

```http
POST https://sso.tri.local/realms/tri/protocol/openid-connect/token
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code
&client_id=<CLIENT_ID>
&client_secret=<CLIENT_SECRET>
&code=<回调拿到的 code>
&redirect_uri=<与授权请求完全相同>
&code_verifier=<第 2 步生成的 verifier 原文>
```

成功响应（HTTP 200）：

```json
{
  "access_token": "eyJ...",
  "expires_in": 300,
  "refresh_expires_in": 28799,
  "refresh_token": "eyJ...",
  "token_type": "Bearer",
  "id_token": "eyJ...",
  "session_state": "…",
  "scope": "openid profile email roles"
}
```

失败：HTTP 400 + `{"error":"invalid_grant","error_description":"..."}`

| error | 含义 | 处理 |
|---|---|---|
| `invalid_grant` | code 已被用过/过期（60 秒）/verifier 不匹配/redirect_uri 不一致 | 检查是否重复使用 code；verifier 是否原样 |
| `invalid_client` | secret 错 | 核对 secret（不要有空格/换行） |

## 4. ID Token 的字段（要校验的和要用的）

```json
{
  "iss": "https://sso.tri.local/realms/tri",
  "aud": "<CLIENT_ID>",
  "sub": "3f2b…-uuid",                    ← 用户主键（永不变）
  "preferred_username": "linyiyao",       ← 域账号，仅用于展示/首次对账
  "name": "张三",
  "email": "zhangsan@traceic.com",
  "nonce": "<你发出去的 nonce>",
  "azp": "<CLIENT_ID>",
  "exp": 1793249000,
  "iat": 1793248700
}
```

**必须逐项校验**：

| 字段 | 规则 |
|---|---|
| 签名 | RS256，用 JWKS 里 `kid` 匹配的公钥验签；**不接受 `alg: none`** |
| `iss` | 必须等于 `https://sso.tri.local/realms/tri` |
| `aud`（或 `azp`） | 必须包含你的 clientId |
| `exp` / `nbf` | 允许 ±60 秒时钟偏差 |
| `nonce` | 必须等于你登录时发出的值 |

## 5. Access Token 里的角色

```json
{
  "sub": "3f2b…",
  "realm_access": { "roles": ["kb:admin", "kb:reviewer", "default-roles-tri", "offline_access", "uma_authorization"] },
  "scope": "openid profile email roles"
}
```

只取业务角色，忽略内建角色：

```python
INTERNAL = {"offline_access", "uma_authorization", "account", "default-roles-tri"}
roles = [r for r in claims["realm_access"]["roles"] if r not in INTERNAL and not r.startswith("default-roles")]
```

当前可用业务角色：`ts:admin`、`ts:finance`、`kb:admin`、`kb:reviewer`、`cluster:admin`
（你的系统需要别的角色，向 IT 提需求。）

## 6. UserInfo（取 AD 组时用）

```http
GET https://sso.tri.local/realms/tri/protocol/openid-connect/userinfo
Authorization: Bearer <access_token>
```

需要请求 `groups` scope 才有 `groups` 字段：

```json
{
  "sub": "3f2b…",
  "preferred_username": "linyiyao",
  "email": "linyiyao@traceic.com",
  "groups": ["Group_AgenticFlow", "Group_AllStaffs", "Group_BackupEnd", "Group_Roots"]
}
```

- 组名不带 `/` 前缀、不区分大小写（比较时统一小写）。
- 只包含**你这个人所在的组**，不是全量目录。
- **不要在业务逻辑里硬编码组名** —— 组名是过渡手段，最终用角色。

## 7. 登出

```
GET https://sso.tri.local/realms/tri/protocol/openid-connect/logout
    ?client_id=<CLIENT_ID>
    &post_logout_redirect_uri=<你登记的登出后回跳地址>
    [&id_token_hint=<登录时的 id_token>]
```

- 前端必须**整页跳转**（`location.href`）；
- 不要用 fetch：即使返回 200，浏览器里的 IdP 会话 cookie 不一定被清；
- 登出后再打开其它已接入系统，应要求重新登录（这是验收项）。

## 8. 复制即用的 curl 自测

### 8.1 看 discovery（确认网络与证书）

```bash
curl -s --cacert tri.local_ca.crt \
  https://sso.tri.local/realms/tri/.well-known/openid-configuration | head -20
```

### 8.2 用代码换令牌（浏览器登录后把地址栏的 code 贴进来，60 秒内）

```bash
CODE='粘贴 code'
VERIFIER='你生成的 verifier 原文'
curl -s --cacert tri.local_ca.crt \
  -X POST https://sso.tri.local/realms/tri/protocol/openid-connect/token \
  -d grant_type=authorization_code \
  -d client_id='<CLIENT_ID>' \
  -d client_secret='<CLIENT_SECRET>' \
  -d redirect_uri='<回调地址>' \
  -d code="$CODE" -d code_verifier="$VERIFIER" | python3 -m json.tool
```

### 8.3 解开 ID Token 看字段（只看不验签，调试用）

```bash
TOKEN='粘贴 id_token'
python3 -c "import base64,json,sys;p=sys.argv[1].split('.')[1];p+='='*(-len(p)%4);print(json.dumps(json.loads(base64.urlsafe_b64decode(p)),indent=2,ensure_ascii=False))" "$TOKEN"
```

### 8.4 取 userinfo

```bash
curl -s --cacert tri.local_ca.crt \
  -H "Authorization: Bearer <access_token>" \
  https://sso.tri.local/realms/tri/protocol/openid-connect/userinfo | python3 -m json.tool
```

## 9. 有效期与限制（默认值）

| 项 | 值 | 说明 |
|---|---|---|
| 授权码 | 60 秒 | 一次性，**不能重复使用** |
| access_token / id_token | 5 分钟 | 只用于服务端验证，不要缓存太久 |
| 会话（SSO） | 8 小时空闲 / 24 小时上限 | 你的本地会话建议与 8 小时对齐 |
| 登录失败 | 5 次后递增等待 | IdP 统一节流，不要在业务系统里再做一遍 |
| 令牌大小 | 通常 < 3 KB | 不要把令牌塞进 cookie（用会话 id 代替） |
