# ai.tri.local（知识平台）接入 sso.tri.local —— 操作清单

> 目标：员工在知识平台不再输入域口令，改为跳 `sso.tri.local` 登录；一次登录，其它已接入系统免登录。
> 预计工作量：**后端 1 天 + 前端 0.5 天 + 测试 0.5 天**。
> 前置：Keycloak 已部署（✅ client `knowledge-hub` 已存在，**groups scope 已于 2026-11-03 分配**）。

## 0. 先看结论：这个系统与工时系统的差异

| 项 | 知识平台 | 说明 |
|---|---|---|
| 账号/口令登录 | `POST /api/login` | 只有一条，删掉即可 |
| 会话 | 进程内 `SESSION_CACHE` + HMAC 签名 cookie | **不改**，沿用 |
| CSRF | `/api/login`、`/api/me` 下发 `csrf` | **不改**，沿用 |
| 角色 | `employee/submitter/reviewer/admin` | 由 AD 组推导（`ldap.js` 的 `mapRole`） |
| 部门 | `resolveDepartment(groupCns)` | 由 `Group_KB_<KEY>` 组推导，**决定"部门可见范围"** |
| 结论 | **必须请求 `groups` scope** | 否则所有人都变成"无部门"，已共享的部门知识会突然看不到 |

## E. 常见问题

| 现象 | 处理 |
|---|---|
| `invalid_scope: roles+groups` | IdP 侧 client 没分配 groups scope → 已在 2026-11-03 修好；新环境执行 `deploy.sh provision` |
| 登录后所有人都"无部门" | 没请求 groups scope，或 `resolveDepartment` 改造时没把组名传进去 |
| 登录后提示"不在授权范围内" | userinfo.groups 为空（scope 问题）或用户不在 `Group_AllStaffs` |
| 写操作 403 | 登录后没取到 csrf：`/api/me` 应返回 csrf；沿用原逻辑 |
| 退出后其它系统仍登录 | 前端用了 fetch 跳 logoutUrl，必须整页 `location.href` |

## F. 可选：保留自有登录页？

**不建议**（本系统无外包场景）。若将来需要，见 [双登录方案](../../../docs/双登录方案.md)：
本地账号通道必须独立，**不能**在自有登录页继续校验域口令。
