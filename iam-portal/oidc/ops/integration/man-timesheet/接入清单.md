## E. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 点登录后 IdP 报 `Invalid parameter: redirect_uri` | `.env` 的 `OIDC_REDIRECT_URI` 与 IdP client 白名单不一致（必须是 `https://man.tri.local/api/auth/oidc/callback`） |
| 回调报 `Login session expired` | state 已用过或超过 10 分钟；刷新重试。多实例部署时 pending 必须放共享存储 |
| 登录成功但提示"不在授权范围内" | userinfo 的 `groups` 为空 → 检查 client 是否分配了 `groups` scope、用户是否真在 `Group_AllStaffs` |
| 提示"已绑定到另一个 OIDC 主体" | 该本地用户之前绑定过别的 sub（如 IdP 重建）。人工核对后改 `users.oidc_sub` |
| 财务看不见菜单 | 检查 `users.role`（库里的业务角色）与 `LDAP_ADMIN_GROUPS` 推导结果 |
| 登出后其它系统还登录着 | 前端没整页跳转 `logoutUrl`（用了 fetch）→ 必须 `location.href` |

## E2. 可选：保留自有登录页（双登录）

**结论先行**：默认**不做**。如果确实需要（外包/应急），按 [双登录方案](../../../docs/双登录方案.md) 做，
**关键约束：本地登录不能校验域口令，必须走独立的本地账号表**。

需要时追加的工作：

- [ ] 复制 `dual-login/localLogin.js` → `server/src/localLogin.js`，装 `bcryptjs`
- [ ] 执行 `dual-login/migration.sql`（加 `local_password_hash` / `local_login_enabled`）
- [ ] `POST /api/auth/login/local` 路由（只认本地账号，**不再调用 LDAP bind**）
- [ ] 前端 LoginView 增加次要入口「本地账号登录」（默认只对运维/外包可见）
- [ ] `.env` 配 `LOCAL_LOGIN_MODE=off`（上线默认关闭）
- [ ] 验收：域账号在本地登录页**必须失败**；本地账号登录后在审计里 `via=local`

## F. 与其它系统接入的区别

| 项 | man-timesheet 特殊性 |
|---|---|
| 角色来源 | **AD 组仍参与判定**（准入/财务/管理员），所以必须请求 `groups` scope |
| 业务角色 | `users.role` 保留在库里（pm 等业务指派不能进 IdP） |
| 数据库 | 需要新增 `oidc_sub` 列做身份对账 |
| 前端 | 是 Vue SPA，登录页要删口令框、改 401 跳转 |
| 其它系统 | 知识平台/Open WebUI 没有 `pm` 这类业务角色，直接用 IdP 角色即可，改造更简单 |
